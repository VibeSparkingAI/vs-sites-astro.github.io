OpenClaw 2026.4.11-pre Changelog 深度调研

Section titled “OpenClaw 2026.4.11-pre Changelog 深度调研”

概览

Section titled “概览”

这个预发布版本聚焦三个方向：一是 Memory、UI、视频生成、插件声明等能力扩展，二是 Feishu、Teams、Ollama、OpenAI-compatible 这类已有集成的易用性增强，三是 Codex OAuth、转写、Talk Mode、WhatsApp、ACP 流式输出等高频路径的稳定性修复。整体看，这一版不是单点大功能，而是围绕“更强的多模态交互、更清晰的集成边界、更少的内部泄漏和配置摩擦”持续收敛。

主要亮点：

  • 9 项功能增强，覆盖 Dreaming、WebChat、视频生成、插件 setup、Teams/Feishu 等。
  • 12 项修复，重点是 Codex OAuth、音频转写、Talk Mode、ACP/QA 泄漏控制、WhatsApp 路径一致性。
  • 延续 2026.4.10 在 Codex、Active Memory、严格 agentic 执行、provider 分类和 QA 体系上的方向。

新功能 (Features)

Section titled “新功能 (Features)”

Dreaming/memory-wiki: ChatGPT 导入接入 + Imported Insights / Memory Palace 子页

Section titled “Dreaming/memory-wiki: ChatGPT 导入接入 + Imported Insights / Memory Palace 子页”
  • 变更内容： Dreaming 现在能接入 ChatGPT 导入内容，并在 UI 中直接查看 imported source chats、compiled wiki pages 和 full source pages。
  • 问题背景： 之前 Dreaming 更偏向 OpenClaw 内生记忆流，外部导入对用户来说通常是“黑盒进库”，很难核查导入来源、编译后的 wiki 页面以及原始材料之间的映射。
  • 使用场景： 比如用户把一批 ChatGPT 历史对话导入后，希望确认某条偏好是从哪段旧对话抽取出来的，或者在 Dreaming 审核 durable memory 时回溯原文证据。
  • 注意事项： 导入能力会增加记忆源复杂度，升级后要注意导入数据量、索引时延和隐私边界，尤其是共享环境下不要把私密聊天无差别导入。breaking change 迹象不明显，但 UI 和记忆审阅习惯会变化。
  • 历史演进： 2026.4.8 恢复了 memory-wiki 整套栈，2026.4.9 又补上 grounded REM backfill、结构化 diary 视图，这次则进一步把“外部对话导入”和“Dreaming 内部可审计性”接起来，说明记忆系统正从存储走向可核查的知识工作台。
  • 竞品对比： Hermes Agent、NanoClaw 一类通常停留在向量召回或简单 memory append；IronClaw 可能有更强知识图谱，但未必把原始聊天、编译页和 diary UI 串得这么细。OpenClaw 这版更偏“可追溯记忆运营台”。
  • 未来演进： 很可能继续走向多来源导入、冲突检测、证据链可视化、自动摘要校验，甚至把 imported chats 直接转成 claim/evidence 审核流。

Control UI/webchat: 结构化渲染 media/reply/voice 指令 + [embed …] 标签

Section titled “Control UI/webchat: 结构化渲染 media/reply/voice 指令 + [embed …] 标签”
  • 变更内容： WebChat 将 assistant 的 media、reply、voice directives 渲染成结构化 chat bubbles，并新增 [embed …] 富输出标签，同时对外部 embed URL 增加配置门控。
  • 问题背景： 过去这类能力经常以文本约定或隐式格式存在，用户看到的可能是半结构化原始内容，不够直观，也容易把内部协议暴露到用户面前。
  • 使用场景： 例如 agent 返回语音回复、嵌入视频、富媒体卡片，或者把结构化 reply directive 在浏览器端直接显示为可交互气泡，而不是一段难懂文本。
  • 注意事项： 升级时要关注前端自定义渲染、embed 白名单和 CSP/外链安全策略。对已有依赖原始文本输出的脚本或测试，可能需要调整断言。
  • 历史演进： 2026.4.8 已经强化 Control UI 多语言和技能面板，2026.4.10 又简化 Dreaming 场景页，这次继续把 WebChat 从“聊天窗口”往“富交互控制台”推进。
  • 竞品对比： NanoClaw、PicoClaw 常见做法是 markdown + 附件；Hermes Agent 若无定制前端，通常不会把 voice/reply directive 做到这么原生。OpenClaw 现在更接近“协议驱动的原生 agent UI”。
  • 未来演进： 预计会继续加入更完整的富组件协议，例如表单、审批卡片、可恢复任务卡、时间线块等。

Tools/video_generate: URL-only 资产交付、typed providerOptions、参考音频等

Section titled “Tools/video_generate: URL-only 资产交付、typed providerOptions、参考音频等”
  • 变更内容： 视频生成工具新增仅 URL 交付、typed providerOptions、reference audio、asset role hints、自适应宽高比和更高图片输入上限。

    • 对维护者来说，要同步关注 QA parity gate、打包行为和 timeout 策略变化。
  • 未来趋势：
    • OpenClaw 正在从“强功能堆栈”走向“强运维、强可见性、强插件声明式能力平台”。

    • 相比 IronClaw 这类可能强调复杂编排的系统，OpenClaw 的优势在于渠道、打包、运维和 UI 一体化。
    • 相比 PicoClaw、ZeroClaw 这类最小实现，OpenClaw 在插件声明、QA 治理、渠道一致性和多模态 provider 抽象上领先很多，但复杂度也更高。
