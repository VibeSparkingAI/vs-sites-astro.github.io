三个 Agent 同时探索三个代码库，从根本上比一个开发者逐文件顺序阅读要快得多。这三个 Agent 在不到 3 分钟内搜遍了 Rails、Go、TypeScript 和 Angular 代码库中的 200 多个文件。

3. 结构化工作流防止钻牛角尖

Section titled “3. 结构化工作流防止钻牛角尖”

BMAD Quick Dev 的步骤文件架构强制推进流程：

  • 第 1 步： 判断复杂度，确立基准
  • 第 2 步： 收集上下文，定位文件，识别规律
  • 第 3 步： 执行（本例中为综合分析）

没有这个结构，很容易陷在某一个代码库里，把其他的晾在一边。

4. 差距分析优于功能清单

Section titled “4. 差距分析优于功能清单”

最有价值的输出不是”我们需要构建什么”，而是”什么已经存在，差距在哪里”。这从根本上重构了对话框架——从”构建一个账单推送系统要多久”，变成”把现有组件串联起来要多久”——这是本质上更准确的估算方式。

更深层的启示

Section titled “更深层的启示”

这套方法真正的价值不在于速度（尽管 10 分钟 vs. 半天确实香）。它的核心优势在于：在不确定性下依然能做到全面覆盖。

一个人肉探索三个代码库的开发者，大概率会聚焦在自己最熟悉的部分，对其余部分做出假设。而并行 Agent 的方式保证了对三个代码库的均等覆盖，能把哪怕是经验丰富的开发者也未必知道的基础设施都翻出来。

项目经理在一小时内就拿到了答案。这个答案不只是”4-6 天”，而是清楚地说明了什么已经存在、什么还没有、可能出什么问题以及如何应对。这就是估算与评估之间的差距。
