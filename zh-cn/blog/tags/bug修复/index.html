OpenClaw 2026.4.7 Bug 修复深度分析

2026年4月8日
Vibe Sparking

本文档对 OpenClaw 2026.4.7 release 的全部 71 项 Bug 修复逐项进行深度分析。

1. CLI/infer: 推理行为与实际运行时执行对齐

Section titled “1. CLI/infer: 推理行为与实际运行时执行对齐”

修复摘要

Section titled “修复摘要”

修复 openclaw infer CLI 命令在 TTS 覆盖、profile 感知的 gateway TTS 偏好、转录 prompt/语言覆盖、图片输出 MIME/扩展名不匹配、web-search 回退以及 agent 与 CLI web-search 行为漂移等多个方面与实际运行时不一致的问题。

问题背景

Section titled “问题背景”

openclaw infer 作为独立 CLI 推理命令，本应产生与 agent 运行时完全一致的结果。但随着功能迭代，两条路径的实现逐渐分化：TTS 配置未读取 profile 级别偏好、转录时忽略了用户指定的 prompt 和语言参数、图片生成的 MIME 类型与文件扩展名不对应（如返回 PNG 数据但标记为 .jpg）、web-search 在 agent 端有回退逻辑但 CLI 端缺失。根因是 infer 路径与 agent 路径共享代码不足，各自独立演化。

使用场景与影响

Section titled “使用场景与影响”
  • 用户通过 openclaw infer --tts 生成语音时，得到的声音/格式与在 agent 对话中不同
  • 使用 openclaw infer 做图片生成，保存的文件扩展名与实际内容不符，导致部分查看器无法打开
  • CLI 中 web-search 结果与 agent 中不同，造成自动化脚本产出不一致

注意事项

Section titled “注意事项”

升级后无需配置变更。如果之前通过 workaround 手动指定 MIME 类型或 TTS 参数，升级后可以移除这些变通方案。

历次版本相关变化

Section titled “历次版本相关变化”

openclaw infer 最初作为轻量推理入口引入，早期版本与 agent 共享核心路径。随着 agent 侧陆续增加 profile、TTS 偏好、web-search 回退等功能，infer 路径未同步更新，导致渐进式漂移。本次修复统一了两条路径的行为。

同类产品对比

Section titled “同类产品对比”
  • NanoClaw: CLI 推理与 agent 共用同一入口函数，天然一致，但功能较少不存在漂移问题
  • Nanobot: 无独立 infer 命令，所有推理通过 YAML pipeline 执行，不存在此问题
  • IronClaw: 有专门的一致性测试套件确保 CLI 与 API 行为对齐
  • PicoClaw: 仅有 CLI 模式，无 agent 运行时，无漂移风险
  • ZeroClaw: CLI 作为 API 客户端，所有请求走统一 API gateway，架构上避免了分化

未来演进趋势

Section titled “未来演进趋势”

预计 infer 路径将进一步与 agent 运行时合并，通过共享 provider adapter 层消除重复实现。长期可能引入集成测试自动检测 CLI/agent 行为漂移。

2. Plugins/media: 能力插件 ID 合并到 allowlist

Section titled “2. Plugins/media: 能力插件 ID 合并到 allowlist”

修复摘要

Section titled “修复摘要”

当设置了 plugins.allow 时，能力回退逻辑现在会将内置能力插件 ID 合并到允许列表中，使 OpenAI 兼容 STT 等媒体理解提供者无需在 plugins.allow 中显式声明 openai 即可加载。(#62205)

问题背景

Section titled “问题背景”

openclaw 的插件安全模型允许用户通过 plugins.allow 限制可加载的插件。但内置的”能力插件”（如语音转录的 STT provider）属于平台核心功能而非第三方插件。之前的实现仅合并了 plugins.entries 中的 ID，遗漏了内置能力插件 ID，导致在启用了 plugins.allow 的严格环境中，语音转录等核心功能意外不可用。

使用场景与影响

Section titled “使用场景与影响”
  • 用户配置了 plugins.allow 白名单来限制插件加载
  • 发送语音消息后 agent 无法转录，报告找不到 STT provider
  • 必须手动在 plugins.allow 中加入 openai 才能恢复语音转录

注意事项

Section titled “注意事项”

升级后，如果之前为解决此问题在 plugins.allow 中添加了 openai，可以安全移除（除非确实需要 OpenAI 插件的其他功能）。无需额外配置变更。

历次版本相关变化

Section titled “历次版本相关变化”

plugins.allow 白名单机制在较早版本引入用于安全加固。能力插件（capability plugins）概念后来独立于普通插件体系，但 allowlist 合并逻辑未及时更新以覆盖此分类。

同类产品对比

Section titled “同类产品对比”
  • NanoClaw: 插件系统较简单，内置能力不经过插件加载器，不存在此问题
  • Nanobot: 无插件白名单机制，所有配置的组件均可加载
  • IronClaw: 区分”系统插件”和”用户插件”两级，系统插件不受用户白名单限制
  • PicoClaw: 内置功能编译时确定，无动态插件加载
  • ZeroClaw: 使用 RBAC 控制插件访问，内置能力拥有系统级权限，不受租户白名单影响

未来演进趋势

Section titled “未来演进趋势”

预计将引入插件分类标签（如 capability、extension、channel），允许白名单按类别而非逐个 ID 控制。

3. Agents/history and replies: 历史记录与回复对齐

Section titled “3. Agents/history and replies: 历史记录与回复对齐”
