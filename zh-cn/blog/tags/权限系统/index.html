Claude Code 2.1.97 逐项深度解析：50+ 变更全面拆解

2026年4月9日
Vibe Sparking

版本发布日期：2026-04-09 变更数量：50+ 项

版本概览

Section titled “版本概览”

2.1.97 是一个大型维护加功能版本，包含约 50 多项变更，覆盖新功能、权限系统、MCP、会话恢复、NO_FLICKER 渲染、企业集成和大量可靠性修复。整体信号很明确，这一版不是单点创新，而是在把 Claude Code 的核心执行面打磨到更稳定、更适合高频真实开发使用的状态。

一、新增功能

Section titled “一、新增功能”

1. Focus View 切换（Ctrl+O） in NO_FLICKER mode

Section titled “1. Focus View 切换（Ctrl+O） in NO_FLICKER mode”

变更内容

  • 在 NO_FLICKER 模式下新增 Focus View
  • 显示内容包括：用户 prompt、工具调用的一行摘要、编辑 diffstats、最终响应

问题背景

  • NO_FLICKER 模式解决了传统终端刷屏闪烁问题，但也带来了另一个问题，长会话里信息层次容易混杂
  • 用户常常不想看全部原始工具输出，而是想快速理解“我问了什么、它做了什么、改了多少、最后答了什么”

使用场景

  • 长时间重构任务后的快速审阅
  • 向同事复盘一次 agent 工作过程
  • 在大量 Bash、Read、Edit、Write 工具调用后做结果回看
  • 需要快速定位一次失败任务的操作摘要

例子

  • 用户让 Claude 重构 auth 模块
  • Focus View 中只显示：
    • prompt: “Refactor auth to JWT middleware”
    • tool summary: Read 4 files, Edit 3 files, Bash npm test
    • diffstats: +84 -27
    • final response: “JWT middleware refactor completed, tests pass”

注意事项

  • 只在 NO_FLICKER 模式中可用
  • 更适合摘要浏览，不适合替代完整逐步调试
  • 如果你需要精细看每一步 shell 输出，仍然要回完整视图

历史关联变更

  • 2.1.89 引入 CLAUDE_CODE_NO_FLICKER=1
  • 2.1.90 到 2.1.97 连续修复多项 NO_FLICKER 渲染、滚动、复制、快捷键问题
  • 本次加入 Focus View，说明 NO_FLICKER 从“实验渲染层”进入“可用工作流界面”阶段

竞品对比

  • Codex CLI
    • 通常更偏原始流式输出
    • 没有这个层次化焦点回顾视图
  • Gemini CLI
    • 更强调结构化输出和扩展生态
    • 也缺少这种面向长 coding session 的会话摘要视图

未来趋势判断

  • 后续可能出现更多视图切换，比如 diff-only、tools-only、errors-only
  • Claude Code 可能会逐渐把终端会话演进成一个“可导航工作记录界面”而不只是文本流

2. refreshInterval status line 设置

Section titled “2. refreshInterval status line 设置”

变更内容

  • 新增 refreshInterval 状态栏设置
  • 可让状态栏命令每 N 秒自动重跑

问题背景

  • 之前状态栏更像静态信息或低频更新
  • 对于实时变化信息，比如当前分支状态、任务队列、后台服务健康状态，单次渲染不够

使用场景

  • 实时展示 git branch、worktree、repo 状态
  • 实时展示本地 dev server、测试 watcher、CI 状态
  • 在远程开发时显示当前机器状态或 session 信息

例子

  • 每 5 秒执行一个状态命令，显示：
    • 当前 branch
    • 当前 worktree
    • 后台测试是否通过
    • 当前目录是否有未提交修改

注意事项

  • 刷新太频繁会增加性能开销
  • 状态栏命令应尽量轻量，避免引发卡顿
  • 在大型 monorepo 中执行重型 git/status 命令时要特别小心

历史关联变更

  • 2.1.94 增加更丰富的状态/UI 信息管理
  • 2.1.97 同时增加 workspace.git_worktree，这两个变更明显是配套的

竞品对比

  • Codex CLI 状态 UI 相对简洁，没有这种明显可编排的状态栏刷新机制
  • Gemini CLI 有 footer/UI 改进，但对“自定义状态命令定时刷新”的支持没有 Claude Code 这么偏开发工作流化

未来趋势判断

  • 状态栏后续可能支持更多动态上下文，如 token 使用、agent 数量、任务状态、网络状态
  • 长期看可能演化成可定制开发 cockpit

3. workspace.git_worktree 注入状态栏 JSON

Section titled “3. workspace.git_worktree 注入状态栏 JSON”

变更内容

  • 当当前目录位于 linked git worktree 中时，状态栏 JSON 输入新增 workspace.git_worktree

问题背景

  • Git worktree 是高频高级开发用法，特别适合并行修 bug、并行做 feature、并行跑 agent
  • 很多工具只感知 repo root，不感知当前 worktree 身份，导致状态误导

使用场景

  • 一个仓库开多个 worktree 同时做不同分支任务
  • 一个 Claude 主会话 + 多个 subagent 分别绑定不同 worktree
  • 通过状态栏快速确认自己当前不在主工作目录，而是在某个 linked worktree

例子

  • 主仓库在 /repo
  • 当前目录在 /repo-feature-auth
  • 状态栏可显示 worktree=feature-auth

注意事项

  • 只有 linked worktree 场景下才有值
