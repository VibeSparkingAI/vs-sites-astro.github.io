2026年3月26日
Vibe Sparking

OpenClaw v2026.3.24 正式版

Section titled “OpenClaw v2026.3.24 正式版”

五天四个版本。v2026.3.22 破纪录发布，v2026.3.23 紧急修了 29 个 bug，v2026.3.24-beta.1 带来 18 项功能变更和 40+ 修复，beta.2 做了一轮 RC 验证。现在正式版出来了，beta.1 的全部功能进入稳定通道，外加 27 项缺陷修复。

这篇文章不重复 beta.1 已经讲过的内容，重点放在正式版新增的修复、安全变更，以及从 beta 到稳定版的演进路径。

参考：GitHub Release v2026.3.24

从 beta 到正式版：3 天的收敛过程

Section titled “从 beta 到正式版：3 天的收敛过程”

版本演进路径：

beta.2 只挑了 3 个修复做验证，2.5 小时后推正式版。这种节奏说明团队对 beta.1 的质量有信心，beta.2 更像一次冒烟测试而非大规模回归。

功能变更：beta.1 内容回顾

Section titled “功能变更：beta.1 内容回顾”

正式版的 18 项功能变更与 beta.1 完全相同，没有新增也没有删减。如果你已经读过 beta.1 的文章，可以跳过这部分。

简要列出关键变更：

  • Gateway：新增 /v1/models 和 /v1/embeddings 端点，model 参数透传
  • Teams：迁移到官方 SDK，支持流式回复、欢迎卡片、AI 标注
  • Teams：消息编辑和删除
  • Skills：7 个内置技能添加安装元数据，CLI 和 UI 可引导依赖安装
  • Control UI：技能管理界面大改，状态过滤 + 详情对话框
  • Slack：恢复富交互一致性，Options: 自动渲染为按钮
  • CLI：--container 参数支持 Docker/Podman 容器内执行
  • Discord：LLM 生成线程标题
  • Plugins：before_dispatch 钩子
  • Control UI/macOS：6 项 UI 改进（文件预览、树形导航、模型选择器等）
  • Runtime：Node 22 最低版本降至 22.14
  • CLI：升级前预检 Node 版本

安全修复：媒体路径别名绕过沙箱

Section titled “安全修复：媒体路径别名绕过沙箱”

这是本版本最值得关注的修复。

问题：通过 mediaUrl 或 fileUrl 别名字段，出站工具可以绕过 media-root 限制，访问沙箱外的文件。恶意 prompt injection 可以诱导 agent 用 fileUrl 读取 /etc/passwd 然后发送到外部。

根因：安全边界检查只覆盖了主路径字段，别名字段没管。

影响范围：运行多租户 OpenClaw 的环境风险最高。单用户部署受影响较小，但仍然建议升级。

路径遍历和别名绕过是 Web 安全的老问题了。Jupyter Notebook、Code Server 都出过类似漏洞。OpenClaw 这次修复把所有路径字段统一纳入安全检查。

缺陷修复：正式版 16 项

Section titled “缺陷修复：正式版 16 项”

出站媒体/本地文件：策略对齐

Section titled “出站媒体/本地文件：策略对齐”

workspaceOnly 关闭时，agent 发送宿主机本地文件会失败。根因是文件发送的权限判断和读写文件用了两套逻辑。如果你之前用 workaround（手动 copy 到 workspace）解决过这个问题，现在可以去掉了。

Gateway 重启后会话恢复

Section titled “Gateway 重启后会话恢复”

之前 gateway 重启后，被中断的会话只收到一条”尽力恢复”的通知，thread/topic 路由信息可能丢失。现在走心跳唤醒流程，保留路由信息，出站失败自动重试一次。

Docker 首次安装启动循环

Section titled “Docker 首次安装启动循环”

全新 Docker 安装时，CLI 在 gateway 启动前就尝试连接写配置，形成死循环。改为通过 gateway 进程直接写入，绕过网络依赖。对已有部署无影响。

通道启动故障隔离

Section titled “通道启动故障隔离”

Telegram bot token 过期了，不仅 Telegram 不工作，Discord 和 WhatsApp 也一起挂。原因是通道启动串行执行且没有 try-catch 隔离。现在单个通道故障被隔离，其他通道正常启动。这是隔舱模式（bulkhead pattern）的应用。

WhatsApp 回声抑制

Section titled “WhatsApp 回声抑制”

群组中 gateway 发送的消息被当作新入站消息再次处理，形成回复循环。同时误杀了 owner 从链接账户发出的 /status 命令。修复方式：跟踪最近发送的消息 ID，只抑制匹配的回声。

WhatsApp 回复检测

Section titled “WhatsApp 回复检测”

用户在群组中回复 bot 消息来触发 bot，但回复检测失效。根因是 bot 的 selfLid 读取方式变了。WhatsApp 的链接账户模式让 bot 和 owner 共享一个号码，这是架构层面的复杂性来源。

Telegram 论坛 #General 话题路由

Section titled “Telegram 论坛 #General 话题路由”

Telegram 论坛模式的 #General 话题（topic ID = 1）在 Telegram 省略 forum 元数据时路由失败。如果你在 Telegram 论坛群中用 OpenClaw，这个修复必须升级。
