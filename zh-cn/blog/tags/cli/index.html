一、先说结论

Section titled “一、先说结论”

1. OpenClaw CLI 本身不负责发布 skill

Section titled “1. OpenClaw CLI 本身不负责发布 skill”

openclaw skills 目前主要是：

  • 搜索 skill
  • 安装 skill
  • 更新 skill
  • 查看本地 skill 信息

它没有 publish 子命令。

2. ClawHub 发布要用独立的 clawhub CLI

Section titled “2. ClawHub 发布要用独立的 clawhub CLI”

也就是说：

  • 安装 / 搜索 / 更新本地 OpenClaw skill → 常用 openclaw skills
  • 发布到 ClawHub registry → 用 clawhub

这是两个不同层级的工具：

  • openclaw 面向 OpenClaw 本地工作流
  • clawhub 面向 ClawHub registry 操作

3. ClawHub CLI 支持 token 登录和 skill 发布

Section titled “3. ClawHub CLI 支持 token 登录和 skill 发布”

这次已经验证通过：

  • clawhub login --token <clh_...> 可以直接登录
  • clawhub publish <folder> --version <semver> 可以发布 skill

所以如果后面要批量发布、自动化发布或者在无头环境里发布，token 方式是可行的。

OpenClaw 的斜杠命令是你与 Gateway 直接交互的快捷通道——不经过模型，不消耗 token，即时执行。掌握它们，就是掌握了 OpenClaw 的操控面板。

一、命令体系概览

Section titled “一、命令体系概览”

OpenClaw 的命令分三层：

类型特征示例
Commands独立消息，Gateway 直接处理/help、/stop、/kill
Directives可内联在消息中，模型看不到/think、/model、/fast
Text-only仅文本聊天可用! ls -la、/compact

核心区别： Directive 单独发送时会持久化到 session；嵌在普通消息里只对当条生效。这个区别很重要——后面会反复提到。

权限模型

Section titled “权限模型”

不是所有人都能用命令。授权链路：

  1. 如果配了 commands.allowFrom → 只看这个，其他全忽略
  2. 否则 → channel allowlist + pairing + commands.useAccessGroups
  3. 未授权 sender 的命令消息 → 静默丢弃，inline /... 当普通文本

快速路径

Section titled “快速路径”

Command-only 消息（整条只有命令）走 fast path：不进队列、不过模型、不需要 @提及（群聊中）。这意味着 /stop 永远能立即生效，哪怕模型正在疯狂输出。

安全修复：媒体路径别名绕过沙箱

Section titled “安全修复：媒体路径别名绕过沙箱”

这是本版本最值得关注的修复。

问题：通过 mediaUrl 或 fileUrl 别名字段，出站工具可以绕过 media-root 限制，访问沙箱外的文件。恶意 prompt injection 可以诱导 agent 用 fileUrl 读取 /etc/passwd 然后发送到外部。

根因：安全边界检查只覆盖了主路径字段，别名字段没管。

影响范围：运行多租户 OpenClaw 的环境风险最高。单用户部署受影响较小，但仍然建议升级。

路径遍历和别名绕过是 Web 安全的老问题了。Jupyter Notebook、Code Server 都出过类似漏洞。OpenClaw 这次修复把所有路径字段统一纳入安全检查。
