引言

Section titled “引言”

Cursor 团队最近发表了一篇优秀的博客文章，分享了他们使用 AI Agent 编程的最佳实践。随着 AI 驱动的开发工具成为主流，理解如何有效地与 AI Agent 协作，正成为开发者必备的核心技能。

这些见解不仅适用于 Cursor，对于任何使用 Claude Code、GitHub Copilot 或类似 AI 编程助手的开发者都极具价值。

8 大核心原则

Section titled “8 大核心原则”

1. 先计划再动手

Section titled “1. 先计划再动手”

让 Agent 先列出步骤、提出问题、确认思路，然后再写代码。虽然这看起来会更慢，但实际上更快。

核心洞察： 如果做出来的结果不对，与其反复修补，不如回退代码、修改计划、重新执行一遍。

2. 上下文别给太多

Section titled “2. 上下文别给太多”

Agent 自己会搜索信息，不需要手动塞一堆文件进去。事实上，提供太多上下文反而会干扰 Agent 的判断。

  • 如果知道具体需要哪些文件，直接指定
  • 如果不确定，让 Agent 自己去找

3. 长对话会失焦

Section titled “3. 长对话会失焦”

换任务时开新对话。如果发现 Agent 反复犯同样的错误，也重新开始。

提示： 可以引用历史工作，不需要复制粘贴所有内容。

4. 规则按需加

Section titled “4. 规则按需加”

只在 Agent 反复犯同一个错误时才写规则，不要提前优化。

保持规则精简，引用文件而不是复制内容。

5. 给可验证的目标

Section titled “5. 给可验证的目标”

写测试、配置 linter、使用类型语言。Agent 需要明确的对错信号才能有效迭代。

TDD 流程特别适合 Agent： 先写测试，再让 Agent 写代码直到测试通过。

6. 图片比文字快

Section titled “6. 图片比文字快”

对于 UI 问题或设计规范，截图和设计稿比文字描述高效得多。

7. Prompt 要具体

Section titled “7. Prompt 要具体”

不要说：“给 auth.ts 加测试”

试试：“给 auth.ts 写测试覆盖 logout 边界情况，使用现有测试模式，不要使用 mock”

指令越具体，结果越好。

8. 认真审查

Section titled “8. 认真审查”

AI 生成的代码可能看起来正确但包含微妙错误。Agent 跑得越快，审查就越重要。

实践方法： 结合 Review Agent 使用。可以使用 Cursor 内置的 Review → Find Issues 功能，或集成外部审查工具。

核心理念

Section titled “核心理念”

把 Agent 当作有能力的协作者，而不是代码生成器。 给它计划、目标、反馈，它才能真正发挥作用。

这些技巧不仅适用于 Cursor，也适用于任何 Agent 工具。

推荐工作流程

Section titled “推荐工作流程”
  1. 规划阶段： 让 Agent 列出实施方案
  2. 目标设定： 定义可验证的成功标准（测试、类型）
  3. 迭代开发： Agent 写代码，你审查
  4. 纠偏调整： 需要时回退并修改计划
  5. 最终审查： 仔细检查生成的代码

结语

Section titled “结语”

软件开发的未来是人机协作。通过遵循这些最佳实践，你可以在保持代码质量的同时，大幅提升开发效率。

记住：Agent 是强大的工具，但你仍然是架构师。你的角色从编写每一行代码，转变为提供愿景、反馈和验证。

UI Skills：帮助 AI 代理构建更好界面的意见性约束

简介

Section titled “简介”

随着 AI 编码助手在构建用户界面方面变得越来越强大，一个新的挑战出现了：一致性。虽然代理可以编写功能正常的代码，但它们经常产生设计模式各异、样式不一致、存在无障碍问题的界面。UI Skills 应运而生——这是一套意见性约束，旨在帮助代理交付更好、更一致的界面。

什么是 UI Skills？

Section titled “什么是 UI Skills？”

UI Skills 是一组意见性 UI 约束，作为 AI 代理构建用户界面的护栏。当被调用时，这些约束确保：

  • 界面遵循一致的设计模式
  • 默认内置无障碍最佳实践
  • 性能默认优化
  • 代码保持可维护和可扩展

该项目支持多个 AI 编码环境，包括 Claude Code、Cursor、OpenCode 以及其他接受技能定义的工具。

为什么意见性约束很重要

Section titled “为什么意见性约束很重要”

在 AI 生成 UI 的世界中，意见性约束具有几个关键作用：

1. 跨代理一致性

Section titled “1. 跨代理一致性”

没有约束，不同的代理（甚至同一代理在不同时间）可能会产生截然不同的实现。UI Skills 为设计决策建立了单一的事实来源。

2. 默认无障碍

Section titled “2. 默认无障碍”

许多 AI 生成的界面会忽略无障碍性。UI Skills 从一开始就强制使用无障碍模式，确保符合 WCAG 标准，无需人工干预。

3. 性能优化

Section titled “3. 性能优化”

代理通常选择最简单的实现路径，而不是性能最佳的路径。UI Skills 将选择限制在经过验证的性能模式上。

Section titled “核心约束类别”

1. 组件

Section titled “1. 组件”

UI Skills 强制执行以下组件级规则：

规则理由
为仅图标按钮添加 aria-label屏幕阅读器可访问性
对破坏性操作使用 AlertDialog防止意外数据丢失
使用结构骨架进行加载状态感知性能提升
永不使用 h-screen，使用 h-dvh移动视口兼容性
为固定元素遵守 safe-area-inset刘海/设备兼容性
在操作旁边显示错误更好的用户反馈
永不在输入中阻止粘贴用户体验增强

2. 动画

Section titled “2. 动画”

动画约束专注于性能和用户体验：

规则理由
除非明确要求，否则不添加动画减少晕动症
仅动画合成器属性（transform, opacity）60fps 性能
永不动画布局属性昂贵的重排
避免动画绘制属性（background, color）GPU 优化
入场使用 ease-out自然的运动感
交互反馈永不超过 200ms响应式感觉
屏幕外时暂停循环动画电池/资源节约
遵守 prefers-reduced-motion无障碍合规
避免动画大图性能优化

3. 排版

Section titled “3. 排版”

排版约束确保可读性：

规则理由
标题使用 text-balance改善视觉居中
正文/段落使用 text-pretty更好的换行
数据使用 tabular-nums防止布局偏移
密集 UI 使用 truncate/line-clamp内容适配
除非要求，否则不修改 letter-spacing字体设计师意图

4. 布局

Section titled “4. 布局”

布局规则保持 z-index 的合理性：

规则理由
使用固定的 z-index 比例防止 z-index 战争
方形元素使用 size-*代码简洁性

5. 性能

Section titled “5. 性能”

性能约束防止常见反模式：

规则理由
永不动画大型 blur() 表面GPU 内存
永不在活动动画外应用 will-change浏览器优化
永不将 useEffect 用于渲染逻辑防止不必要的渲染

6. 设计

Section titled “6. 设计”

设计约束确保视觉一致性：

规则理由
除非要求，否则不使用渐变更简洁的美学
永不使用紫色/多色渐变避免趋势
永不将发光效果作为主要示能性可访问性
除非要求，否则使用 Tailwind 默认阴影一致性
为空状态提供一个明确的下一步操作用户引导
每个视图限制强调色为一个视觉层次
在新颜色之前使用现有主题颜色设计系统完整性

OpenContext：AI 助手的个人上下文存储系统

2026年1月15日
Vibe Sparking

简介

Section titled “简介”

在使用 Claude Code 或 Cursor 等 AI 助手时，一个持续的挑战浮现出来：上下文会丢失。在不同的项目、日期或聊天会话中，你发现自己反复解释背景、重复设计决策，有时 AI 甚至会基于错误的假设继续工作。

OpenContext 通过提供一个轻量级的个人上下文/知识库解决了这个问题，AI 代理可以从中读取和写入——为你的 AI 助手提供持久记忆。

OpenContext 解决的问题

Section titled “OpenContext 解决的问题”
使用 OpenContext 之前使用 OpenContext 之后
📂 难以跨仓库/会话共享上下文✅ 全局上下文库适用于所有项目
🤷 你的想法无法被 Agent 快速理解✅ Agent 自动加载你的背景和决策
🔒 现有知识无法被编码 Agent 操作✅ Agent 可以直接读/写你的知识库

Section titled “包含的功能”

OpenContext 提供了全面的上下文管理工具包：

  • oc CLI — 管理全局 contexts/ 库（文件夹、文档、清单、搜索）
  • MCP 服务器 — 让 Cursor/Agent 将 OpenContext 作为工具调用
  • 桌面应用 — 使用原生 UI 管理/搜索/编辑上下文
  • Web UI — 无需安装即可在本地浏览/编辑上下文
