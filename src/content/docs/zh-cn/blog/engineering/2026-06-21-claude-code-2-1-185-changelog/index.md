# Claude Code 2.1.185：流式等待提示更准确，卡顿体感更温和

Claude Code `2.1.185` 是一版非常小的更新。根据源报告，这个版本只有一项变更：当 API 流式响应长时间停滞时，提示文案从 `No response from API · Retrying in ...` 改成了 `Waiting for API response · will retry in ...`，同时触发等待提示的阈值从 10 秒延长到了 20 秒。

它不是功能扩张版，也不是架构调整版，更像一次很克制的体验修正。改动很小，但指向很明确：让等待状态更像“正在恢复”，而不是“看起来像报错”。

## 版本概览

- 版本：`2.1.185`
- 类型：小幅体验优化
- 核心变更：流式等待提示文案优化，静默阈值从 10 秒改为 20 秒
- 风险判断：低

## 这次到底改了什么

### 1. 提示文案更贴近真实状态

旧文案 `No response from API` 容易让人第一眼觉得请求失败了，尤其是在长时间思考、网络抖动或者后端暂时拥塞的时候。

新文案改成 `Waiting for API response` 之后，语气明显更中性，也更符合实际状态。它传递的不是“已经坏了”，而是“还在等，稍后会重试”。

### 2. 等待提示出现得更晚

触发阈值从 10 秒延长到 20 秒，说明这次更新不仅改了措辞，也在调用户感知。

10 秒的静默在某些网络环境里太敏感了，容易把短暂延迟放大成焦虑。20 秒会更宽容一点，能减少不必要的提示闪现，也能避免用户频繁被打断。

### 3. 目标不是“更激进”，而是“更少误判”

这类改动的价值不在于提供新能力，而在于减少误会。

当一个 CLI 或 agent 工具在等待 API 时，真正重要的是状态表达要准。提示太像错误，会让用户提前中断；提示太早出现，也会让工具显得不稳定。2.1.185 选择往“更准确、更耐心”那边调。

## 为什么这版仍然值得记一笔

### 对日常使用的影响

如果你经常让 Claude Code 跑较长的任务，这类提示优化会直接影响体感：

- 你会更少把短暂卡顿误解成失败
- 你会更少在 10 秒左右就开始怀疑连接是否异常
- 你看到的状态会更接近“系统正在等恢复”，而不是“它已经出问题了”

### 对产品节奏的信号

从版本号上看，`2.1.185` 也是一种很典型的稳定化信号。

当一个产品开始把注意力放到提示文案、阈值和等待状态这些细节上，通常意味着核心链路已经相对稳定，后续更多是在打磨边界体验，而不是改大功能。

## 风险与兼容性

- 这是低风险更新，没有 API 变更，也没有配置迁移。
- 如果你依赖旧提示文案做自动化匹配，可能需要更新规则。
- 20 秒阈值意味着一些原本会更早出现的提醒，现在会更晚出现；这通常是好事，但排障时要记得这个变化。

## 升级建议

1. 如果你已经在用 Claude Code，建议直接跟进。
2. 如果你之前对 `No response from API` 这类提示比较敏感，这版会明显更舒服。
3. 如果你有监控、日志解析或录屏标注脚本，检查是否依赖了旧文案。

## 总结

Claude Code `2.1.185` 不是一版会带来大量新功能的更新，但它把一个很常见的交互痛点磨平了：流式卡顿时的提示更准确了，等待阈值也更合理了。

这种改动通常不显眼，却很容易改善“每天用起来顺不顺”的感觉。对重度用户来说，这已经足够值得升级。
