# Spec Kit v0.11.3 Changelog：补丁版把扩展隔离、任务转 Issue 和 /analyze 安全性一起补齐

Spec Kit `v0.11.3` 是一版很典型的补丁更新：没有大功能宣言，没有架构重写，但把几个对真实使用很敏感的点补得更稳了。最值得看的三个方向分别是扩展加载隔离、`taskstoissues` 的幂等性，以及 Claude Code 里 `/analyze` 子代理的 fork 行为。

如果你已经在 `0.11.x` 系列里，这版基本属于“应该升级，但不用紧张”的类型。它更像是在告诉你：Spec Kit 的工作流底座已经开始进入稳定打磨阶段，接下来重点会放在边界行为、Agent 安全和扩展生态的可维护性上。

## 版本概览

- 版本：`v0.11.3`
- 发布时间：`2026-06-19 19:20:40 UTC`
- 类型：stable release
- 核心关键词：扩展隔离、任务转 Issue、Agent 披露、Monorepo 初始化
- 升级风险：低

## 这次最值得关注的 4 个变化

### 1. 单个扩展失败，不再拖垮整个扩展加载流程

这是这版最实用的稳定性修复之一。此前如果某个扩展加载失败，整个扩展集合都可能被丢弃；现在逻辑更像“逐个容错”，一个扩展出问题不会连坐其他扩展。

对装了多个社区扩展的人来说，这个修复很重要。它意味着你不必因为一个第三方扩展的小错误，就把整个工作流生态都牺牲掉。

### 2. `taskstoissues` 终于更像一个幂等命令了

`taskstoissues` 之前的问题在于：如果任务已经关联了 GitHub Issue，它还可能继续尝试创建新的 Issue。v0.11.3 把这件事补齐了，命令现在会跳过已有关联的任务。

这类修复看起来不“显眼”，但非常影响自动化质量。一个 workflow 命令如果不幂等，重复执行就会制造重复工单、重复通知和额外清理成本。现在这个坑被填上后，自动化回放和批处理会安心很多。

### 3. `/analyze` 迁移到 forked subagent，分析上下文更干净

Claude Code 中的 `/analyze` 现在是在 fork 的子代理里运行。这个变化的意义不只是“换了个执行方式”，而是把分析任务从当前会话状态里隔离出来，减少上下文污染。

对 Agent 系统来说，这是一种更成熟的设计：分析和决策最好不要被历史对话、临时工具状态或其他中间上下文干扰。换句话说，这次更新是在往“更可复现、更可解释”的方向走。

### 4. `SPECIFY_INIT_DIR` 让 Monorepo 初始化更顺手

新增的 `SPECIFY_INIT_DIR` 环境变量，解决的是很具体但很常见的 Monorepo 问题：你想在仓库根目录执行初始化，但真正的成员项目在子目录里。

有了这个变量，`specify init` 可以更自然地落到指定成员路径上，少掉很多手动切目录和重复操作的麻烦。

## 其他值得记住的信号

### Agent 披露要求变得更明确

这版文档强化了 Agent 披露声明，要求明确披露 commits 和每轮评论内容。它不一定会立刻影响所有人的日常使用，但它传递的信号很明确：Spec Kit 正在把 Agent 行为透明度当作正式规范来对待。

如果你的团队在做审计、留痕或合规，这种变化会很有价值。它让工具链不只是“能做事”，也更容易解释“做了什么”。

### 社区扩展生态继续增长

v0.11.3 还带来了 `Token Economy` 扩展，并把 `Multi-Model Review` 等扩展继续往成熟方向推。

对生态型工具来说，补丁版本里还能继续看到扩展目录的推进，通常说明官方已经在把“可装、可拆、可组合”当成长期目标，而不是一次性的演示功能。

### 依赖升级属于顺手收口

`actions/checkout` 从 `6.0.3` 升到 `7.0.0`，以及 `Multi-Model Review` 扩展升级到 `v0.1.2`，这些都不是主菜，但它们说明这版也在持续清理基础依赖和周边扩展的版本边界。

## 如何理解这次发布

如果把 v0.11.0 到 v0.11.3 这一段连起来看，能看到一条很清晰的路线：

1. 先把工作流目录、集成脚手架和扩展生态搭起来。
2. 再把常见的失败模式修掉，比如重复创建 Issue、扩展加载连坐。
3. 然后开始收紧 Agent 的执行边界和披露规范。

这是一条很健康的演进路径。因为真正能长期用的 workflow 工具，最终都不是靠“功能多”，而是靠“出错时不乱、重复执行不炸、扩展越多越稳”。

## 风险与兼容性

- 这是 stable release，不是 prerelease，适合正常升级。
- 主要风险集中在 `/analyze` 的 fork 行为变化，团队需要适应新的隔离模式。
- 如果你依赖扩展链路，升级后建议做一次多扩展加载回归。
- 如果你有 `taskstoissues` 自动化，最好验证重复执行不会再创建重复 Issue。

## 升级建议

1. 如果你已经在 `0.11.x`，可以直接升级到 `v0.11.3`。
2. 如果你使用了多个社区扩展，优先验证扩展加载和失败降级逻辑。
3. 如果你依赖 Claude Code 的 `/analyze`，确认 forked subagent 的结果输出仍符合预期。
4. 如果你在 Monorepo 里使用 `specify init`，试试 `SPECIFY_INIT_DIR` 能否减少目录切换成本。

## 总结

Spec Kit `v0.11.3` 不是一版“惊艳式更新”，但它把几个会直接影响日常稳定性的点补得很扎实：扩展隔离更安全了，`taskstoissues` 更幂等了，`/analyze` 的分析上下文也更干净了。

这类版本最适合的评价不是“新不新”，而是“用起来会不会少踩坑”。从这个角度看，`v0.11.3` 很值得记一笔。
