Claude Code 2.1.73: CPU Freezes Fixed, modelOverrides Added, Opus 4.6 Default Everywhere

Section titled “Claude Code 2.1.73: CPU Freezes Fixed, modelOverrides Added, Opus 4.6 Default Everywhere”

Your terminal locked up. CPU hit 100%. The culprit was a permission prompt for a complex bash command. You had to force-kill the process. 2.1.73 fixes that, along with a set of bugs that share a common trait: they live at the seams where different systems meet.

The freezes

Section titled “The freezes”

Two separate bugs could lock up your entire session.

Permission prompt CPU loop. When Claude Code displayed a permission prompt for a complex bash command, it could enter a tight loop that consumed 100% CPU. The UI froze. No way to respond to the prompt, no way to cancel. Force-kill was the only option. The fix breaks the loop condition that complex command structures triggered.

Skill file deadlock. If many skill files changed simultaneously — the typical scenario is running git pull in a repository with a large .claude/skills/ directory — Claude Code could deadlock. Two internal systems waiting on each other, neither yielding. The result was a complete freeze with no error message. The fix eliminates the circular dependency.

These are the kind of bugs that make you question the tool. Not because they’re frequent, but because when they hit, there’s no recovery except killing the process.

Multi-session bash output

Section titled “Multi-session bash output”

If you had two Claude Code sessions open in the same project directory, bash tool output could be lost. One session’s output would silently vanish. This was a file-level conflict in how sessions shared the output channel.

The fix gives each session its own output path. If you routinely work with multiple terminals in the same project, this was likely causing intermittent confusion where commands appeared to produce no output.

Subagent model downgrades

Section titled “Subagent model downgrades”

This one is subtle. If you configured a subagent with model: opus, model: sonnet, or model: haiku, and you were running on Bedrock, Vertex, or Microsoft Foundry, the subagent would silently receive an older model version. No warning, no error. Your agent just ran on an older model than you expected.

The fix ensures that generic model names resolve to the latest available version on each platform. Combined with the change that makes Opus 4.6 the default on these platforms (previously Opus 4.1), your agents now get the model you actually asked for.

modelOverrides

Section titled “modelOverrides”

The one genuinely new feature. Enterprise users on Bedrock, Vertex, or Foundry can now map model picker entries to custom provider model IDs. The practical use case: Bedrock inference profile ARNs. Instead of being locked to Anthropic’s default model routing, you can point each model picker entry at your own inference profile.

This fills a configuration gap that enterprise users have been working around with various hacks.

SSL certificate errors

Section titled “SSL certificate errors”

Corporate proxies that terminate SSL connections were causing OAuth login and connectivity checks to fail with opaque errors. The fix doesn’t change the behavior — your proxy is still intercepting the connection — but it now tells you what’s happening and points you to NODE_EXTRA_CA_CERTS as the solution.

If you’ve been getting mysterious authentication failures behind a corporate network, check whether your proxy is doing SSL inspection.

Background process cleanup

Section titled “Background process cleanup”

Subagents could spawn bash processes that outlived the agent. When a subagent exited, its background bash processes were not cleaned up. They’d keep running, consuming resources, potentially holding file locks. The fix ensures child processes are terminated when their parent agent exits.

Session and hook fixes

Section titled “Session and hook fixes”

Several fixes in the session lifecycle:

  • /resume was showing the current session in the picker, which is confusing — you’re already in it
  • SessionStart hooks fired twice when resuming via --resume or --continue
  • JSON-output hooks injected no-op system-reminder messages into the model context on every turn, wasting tokens
  • Voice mode sessions could corrupt when a slow connection overlapped with a new recording

Platform fixes

Section titled “Platform fixes”
  • /loop was unavailable on Bedrock/Vertex/Foundry and when telemetry was disabled
  • /ide crashed with “onInstall is not defined” when auto-installing the extension
  • Linux sandbox failed with “ripgrep (rg) not found” on native builds
  • Linux native modules didn’t load on Amazon Linux 2 and other glibc 2.26 systems
  • “media_type: Field required” API error when receiving images via Remote Control
  • /heapdump failed on Windows with EEXIST error when Desktop folder already existed

UX improvements

Section titled “UX improvements”

Up arrow after interrupting. Previously, if you interrupted Claude mid-response and pressed Up, you’d get a blank prompt. Now it restores your interrupted prompt and rewinds the conversation to before the interrupted response, all in one step.

Faster IDE detection. Startup is snappier because IDE detection no longer blocks.

Clipboard image pasting. Performance improved on macOS.

/effort while responding. You can now change effort level while Claude is responding, matching the existing behavior of /model.

Voice mode retry. Transient connection failures during rapid push-to-talk re-presses are automatically retried.

Deprecations

Section titled “Deprecations”

/output-style is deprecated. Use /config instead. Output style is now fixed at session start, which improves prompt caching. This is a trade-off: you lose mid-session style switching, but gain better cache hit rates for the system prompt.

VSCode fix

Section titled “VSCode fix”

HTTP 400 errors for users behind proxies or on Bedrock/Vertex with Claude 4.5 models are fixed. If you use Claude Code in VS Code through a proxy or a non-default provider, this was a blocker.

What 2.1.73 signals

Section titled “What 2.1.73 signals”

If 2.1.72 was a 60-item sweep and 2.1.74 was targeted surgery on trust-critical systems, 2.1.73 sits between them: fixing the seams.

Permission prompts meet complex bash commands. Skill file watchers meet git operations. Multiple sessions meet shared output channels. Generic model names meet platform-specific model registries. Corporate proxies meet OAuth flows. Subagent lifecycles meet bash process management.

Each fix addresses a place where two systems interact and the interaction was handled wrong. None of these bugs were in any single system. They were all in the gaps between systems.

The modelOverrides feature follows the same logic. It exists because the model picker and custom provider configurations were two systems with no bridge. Now there’s a bridge.

For enterprise users running Claude Code across managed infrastructure, 2.1.73 is the release where the tool starts respecting your environment instead of assuming a simple setup.

Notes on AI Apps in 2026: Thinking Tools vs Making Tools

Notes on AI Apps in 2026

Section titled “Notes on AI Apps in 2026”

Source: @illscience | Published: January 5, 2026

Introduction

Section titled “Introduction”

Following excellent 2025 roundup pieces from Karpathy and Simon Willison, Anish Acharya shares his thoughts on what 2026 holds for AI apps. The ecosystem is maturing in expected and surprising ways—we’ve figured out how to make code cheap, but it hasn’t yet diffused across enterprises or the world as implied by those lower costs. We haven’t realized even 10% of what this means for how companies get built and what software will exist.

Thinking Tools vs Making Tools

Section titled “Thinking Tools vs Making Tools”

One major shift expected in 2026 is the nature of tools themselves. All current knowledge work tools focus on execution:

  • IDEs for creating code
  • Figma for creating design
  • Spreadsheets for creating models

When it comes to tools for exploration—tools that help us think—we don’t really have any modern products outside of LLMs themselves emerging as thinking partners.

The Fundamental Problem Shift

Section titled “The Fundamental Problem Shift”

As coding agents work with increasing accuracy and longer time horizons, the hard problem moves from:

“How do I build it?” → “What do I build?”

You can imagine a near-future PM who sets broad goals for their AI and wakes up every morning to review 2-3 features the model dreamt up, executed on, and A/B tested overnight. However, current models still struggle with deciding what to build next—the ideas are bland, derivative, and lack the spark seen in truly innovative product thinking.

The Rise of Exploration-First Tools

Section titled “The Rise of Exploration-First Tools”

The spiritual successors of coding, design, and productivity tools will focus on exploration vs execution:

  • Coding tools are already leading—Cursor is furthest along
  • Antigravity is interesting as “agent-first” (exploration first) in product design

Software Eats All “Service” Functions

Section titled “Software Eats All “Service” Functions”

A critical distinction in software companies:

  • Power functions (engineering/product/performance marketing): closer to software
  • Service functions (legal/finance/HR): further from software, more human-capital levered

Two Implications of Coding Agents

Section titled “Two Implications of Coding Agents”

1. Every team should be software-first All teams (marketing, legal, procurement, finance) must reach for a software toolbox before traditional process/human systems. Options include:

  • Domain-specific products (like Harvey for legal)
  • “Bare metal” coding agents (Codex, Claude Code)

Every team should be a software team.

2. Enterprises can be dramatically more ambitious An enterprise producing software can be dramatically more ambitious in what they produce. The entire ideation/prioritization pipeline must reboot to accommodate this. Every feature that can be built will be built—most enterprises aren’t ready for this reality.

“The culture change problem will be as hard as the organizational change problem.”

Compounding AI Apps

Section titled “Compounding AI Apps”

Entering year two of reasoning models, expect continued divergence between AI-native apps and AI models. Apps will combine:

  • Orchestration of cutting-edge models
  • Domain-specific UI
  • Extensive feature surface (now very cheap to build)

This is the natural implication of “Narrow Startups”—extraordinary specialization is now possible.

Why Apps Won’t Be Subsumed by Models

Section titled “Why Apps Won’t Be Subsumed by Models”

Labs and big tech are about as “jagged” in their capabilities as the models they produce—formidable in focus areas but with:

  • Complex commitments (e.g., Google’s commitments to regulators)
  • Hard prioritization problems (OpenAI simultaneously competing as consumer, enterprise, model, and hardware company)

Even in domains central to model progress like coding, we see a thriving ecosystem—startups generated >$1B of new revenue in 2025 alone.

The “Thick” AI App Framework

Section titled “The “Thick” AI App Framework”

Combining insights:

  • Multi-model orchestration
  • Autonomy slider
  • Context engineering
  • Cornered data resources
  • Network products
  • Ecosystems with extensive feature surface

This is what mature AI apps look like.

Humans Discover “the Rest” of AI

Section titled “Humans Discover “the Rest” of AI”

Eugenia has been the best thinker on how the command-line UI has held back everyday consumers from AI’s best capabilities. This is changing:

  • Wabi: Exposing code generation to consumers
  • Images tab in ChatGPT/Grok: Same for image generation
  • Apps Directory and Skills: Will do the same for MCPs and prompt plugins

Generating a tiny app in 2025 was as delightful as generating a poem in 2023—but most consumers still don’t know this exists.

Notes for (Incumbent) CEOs

Section titled “Notes for (Incumbent) CEOs”

For CEOs already at scale, navigating the AI transition:

  1. Look at best-in-class examples of how models collapse all customer-facing roles (sales, support, collections) into a single function with a broad goal

  2. Embrace being software-first in every function—non-technical functions embracing models is how enterprises get broad operating leverage

  3. Demand more ambitious products and prices—if Tesla can deliver coast-to-coast FSD and Claude Code can be written with Claude Code, we already have AGI for near-term enterprise purposes

Finally… Have Fun

Section titled “Finally… Have Fun”

“No one tells you that you were living in the good old days until they are gone, so consider this your notice.”

This product cycle is:

  • Less centralized
  • More software-led
  • Simply more damn fun for technologists than any in recent memory

Explore these new technologies, discuss their implications, and make more new stuff.
