I. New Features (Added)

Section titled “I. New Features (Added)”

1. managed-settings.d/ Drop-in Policy Directory

Section titled “1. managed-settings.d/ Drop-in Policy Directory”

Added managed-settings.d/ drop-in directory alongside managed-settings.json, letting separate teams deploy independent policy fragments that merge alphabetically

Enterprise deployment pattern: security team deploys 00-security.json (block curl/wget), platform team deploys 10-platform.json (internal MCP servers), business team deploys 20-team-alpha.json (custom Hooks). Files merge alphabetically by filename, numeric prefixes control priority. Similar to Linux’s /etc/sudoers.d/ pattern.

Trend: From single-file → drop-in directory management, the standard pattern for multi-team enterprise collaboration.

2. CwdChanged and FileChanged Hook Events

Section titled “2. CwdChanged and FileChanged Hook Events”

Added CwdChanged and FileChanged hook events for reactive environment management (e.g., direnv)

When Claude switches directories in a monorepo, CwdChanged can auto-run direnv allow to load that directory’s env vars. FileChanged triggers when .env files are modified. Hook events continue to evolve: lifecycle events → tool events → now environment events.

3. sandbox.failIfUnavailable Setting

Section titled “3. sandbox.failIfUnavailable Setting”

Added sandbox.failIfUnavailable setting to exit with an error when sandbox is enabled but cannot start, instead of running unsandboxed

Previously, if sandbox dependencies were missing, Claude Code would silently fall back to unsandboxed execution — a serious security gap. Now enterprises can enforce hard-fail when sandbox can’t start.

Trend: Security policy evolving from “default permissive” → “optionally strict” → eventually “strict by default”.

4. disableDeepLinkRegistration Setting

Section titled “4. disableDeepLinkRegistration Setting”

Added disableDeepLinkRegistration setting to prevent claude-cli:// protocol handler registration

For Docker containers, CI/CD pipelines, and locked-down enterprise environments where protocol handler registration is unnecessary or harmful.

5. CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1

Section titled “5. CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1”

Added CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1 to strip Anthropic and cloud provider credentials from subprocess environments

Prevents malicious prompt injection from stealing API keys via env/printenv. Strips Anthropic + cloud provider (AWS_, GCP_, AZURE_*) credentials from Bash tools, hooks, and MCP stdio servers.

Trend: Supply chain security in AI toolchains. Expected to become default-on in the future.

6. Transcript Search

Section titled “6. Transcript Search”

Added transcript search — press / in transcript mode (Ctrl+O) to search, n/N to step through matches

vim/less-style search in conversation history. Essential for long sessions with hundreds of turns.

7. Ctrl+X Ctrl+E External Editor

Section titled “7. Ctrl+X Ctrl+E External Editor”

Added Ctrl+X Ctrl+E as an alias for opening the external editor (readline-native binding)

Standard readline keybinding for opening $EDITOR. Ctrl+G still works. Aligns with bash/zsh muscle memory.

8. Pasted Image [Image #N] Chips

Section titled “8. Pasted Image [Image #N] Chips”

Pasted images now insert an [Image #N] chip at the cursor so you can reference them positionally

Paste two UI screenshots, type: “Compare the navbar in [Image #1] with [Image #2] and identify differences.”

Trend: Multimodal interaction refinement — from “look at this” to “precisely reference this image”.

9. Agent initialPrompt in Frontmatter

Section titled “9. Agent initialPrompt in Frontmatter”

Agents can now declare initialPrompt in frontmatter to auto-submit a first turn

Agents start executing immediately without waiting for user input. Useful for code review agents that should analyze the current diff on launch.

10. Keybinding Rebinding

Section titled “10. Keybinding Rebinding”

chat:killAgents and chat:fastMode are now rebindable via ~/.claude/keybindings.json

Resolves conflicts with tmux, screen, and other terminal multiplexers.

Claude Code 2.1.81: --bare Mode, Mobile Approvals, and YOLO Mode

Mar 21, 2026
Vibe Sparking

Claude Code 2.1.81: —bare Mode, Mobile Approvals, and YOLO Mode

Section titled “Claude Code 2.1.81: —bare Mode, Mobile Approvals, and YOLO Mode”

2.1.81 doesn’t have any big features—just two noteworthy new flags and a pile of fixes for bugs that quietly bite you in ways you can never quite pin down. Read through each one and you’ll realize this release targets the hardest-to-notice friction in the toolchain.

Two New Flags

Section titled “Two New Flags”

--bare: Scripting Mode, Zero Overhead

Section titled “--bare: Scripting Mode, Zero Overhead”

You’re calling Claude Code with -p in CI or batch scripts, but every time you have to wait for hooks, LSP, plugin sync, and skill directory scanning. All of that makes sense in interactive mode; in an automation pipeline it’s pure waste.

--bare skips all of it:

A few conditions apply: you must provide your key via ANTHROPIC_API_KEY or apiKeyHelper in --settings—OAuth and keychain auth are unavailable in this mode. Auto-memory is also completely disabled.

The use cases are clear-cut: production pipelines, cron jobs, bulk code reviews. Anywhere you don’t need a persistent session, use --bare.

--channels: Tool Approvals Forwarded to Your Phone

Section titled “--channels: Tool Approvals Forwarded to Your Phone”

This feature requires a channel server that supports the permission capability. When that’s in place, Claude’s approval prompts for tool execution no longer block the terminal—they get sent to your phone instead.

You’re in a meeting, away from your desk, and the agent hits a step that needs confirmation. It pops up on your phone; one tap and it continues. No need to walk back to your desk.

For anyone who needs to remotely supervise an agent, this beats everything else.

Bug Fixes: A Dozen Hard-to-Explain Issues

Section titled “Bug Fixes: A Dozen Hard-to-Explain Issues”

Multi-Session OAuth Re-authentication

Section titled “Multi-Session OAuth Re-authentication”

When multiple Claude Code sessions are running simultaneously and one refreshes the OAuth token, the others would be forced to re-authenticate. Now token refreshes no longer affect other sessions.

Running multiple sessions at once is a normal workflow, and this bug would constantly interrupt you in exactly that scenario.

Two Silent Failures in Voice Mode

Section titled “Two Silent Failures in Voice Mode”
  • Retry failures would swallow the error and only show “check your network connection”—now the actual error is displayed.
  • After the server silently dropped a WebSocket connection, audio wouldn’t recover—now it automatically reconnects.

Silent failures are the hardest bugs to debug. You think it’s a network issue when really the tool is lying to you.

CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS Not Working

Section titled “CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS Not Working”

Even with this environment variable set, the structured-outputs beta header was still being sent. Proxy gateways forwarding to Vertex or Bedrock would return 400 because of it.

People actually using this variable had been getting proxy errors without knowing why. Fixed now.

Hyphens in Bash Command Strings Triggering Permission Prompts

Section titled “Hyphens in Bash Command Strings Triggering Permission Prompts”

String arguments containing hyphens (-) in commands would incorrectly trigger permission prompts. A command that should have run silently would instead require manual confirmation. These false alarms erode trust in the tool. Fixed.

Plugin Directory Deleted Mid-Session Causing Blocks

Section titled “Plugin Directory Deleted Mid-Session Causing Blocks”

If the plugin directory got deleted during a session, all subsequent submissions would hang. Plugin hooks no longer block prompt submission.

Race Condition in Background Task Output

Section titled “Race Condition in Background Task Output”

When a background agent task completed between two polling intervals, the output would hang forever. Fixed.

Worktree Session Restoration

Section titled “Worktree Session Restoration”

Restoring a session that was in a worktree now automatically switches back to that worktree. Previously it wouldn’t, and you’d have to cd manually.

/btw Dropping Pasted Content

Section titled “/btw Dropping Pasted Content”

Using /btw during an active response would fail to include the pasted text. Fixed.

Clipboard Race Condition in tmux

Section titled “Clipboard Race Condition in tmux”

Quickly Cmd+Tabbing and then pasting would sometimes paste stale content. The clipboard copy in tmux hadn’t finished before it was read. Fixed.

Several Remote Control Fixes

Section titled “Several Remote Control Fixes”
  • Session titles were always generic names—now they’re derived from the first prompt.
  • /rename didn’t sync the title for Remote Control sessions—now it does.
  • /exit couldn’t reliably archive sessions—now it can.
  • Titles auto-refresh after the third message.

Other

Section titled “Other”
  • Terminal tab titles not updating—fixed.
  • Invisible hook attachments inflating the message count in transcript mode—fixed.

A Few Improvements

Section titled “A Few Improvements”

MCP tool calls collapsed into a single line. Read/search calls used to expand every time; now they’re merged into “Queried {server}”, expandable with Ctrl+O. Cuts down on visual noise quite a bit.

! bash mode is more discoverable. When you need to run an interactive command, Claude now proactively mentions this mode exists. No more digging through docs.

Ref-tracked plugins re-clone on every load. Ensures you get the latest version, not a stale cache.

Plan mode hides the “clear context” option by default. To bring it back, add "showClearContextOnPlanAccept": true.

MCP OAuth supports CIMD / SEP-991. For servers without Dynamic Client Registration, you can now use Client ID Metadata Document for OAuth.

Windows (including WSL in Windows Terminal) disables line-by-line streaming output. Due to rendering issues. WSL in Windows Terminal is also affected.

[VSCode] Windows PATH inheritance fix. The PATH inheritance for the Bash tool when using Git Bash had a regression in v2.1.78—now fixed.

The Last Two Words

Section titled “The Last Two Words”

YOLO mode.

As always.

Claude Code 2.1.80: --channels Lets MCP Servers Push Messages Into Your Session

Claude Code 2.1.80: —channels Lets MCP Servers Push Messages Into Your Session

Section titled “Claude Code 2.1.80: —channels Lets MCP Servers Push Messages Into Your Session”

A Claude Code session has always been a conversation: you talk, the agent responds. MCP servers extended that — the agent could call external tools. But information only flowed one way, outward. The agent asked questions; servers answered them.

2.1.80 opens the reverse channel. --channels (research preview) lets MCP servers push messages into your running session. The tool that could only speak when spoken to just learned to raise its hand.

At a glance

The channel opens both ways

Section titled “The channel opens both ways”

MCP has been a one-way street. Your agent calls a tool, the server responds. That’s it. If something happens on the server side — a CI build fails, a deployment completes, a test suite finishes — the server has no way to tell the agent. You have to ask.

--channels changes this. An MCP server can now push a message into your active session without waiting to be called. Think about what that enables:

A deployment monitor MCP server watching your staging environment. Your agent is writing code. The deploy fails. The server pushes “deploy failed: missing env var DATABASE_URL on staging” directly into the session. The agent sees it, checks the config, fixes it.

A test runner MCP server that pushes results as they complete. Your agent doesn’t have to poll. It gets notified.

A team communication MCP server that pushes relevant Slack messages or PR review comments into your coding session.

This is a research preview, meaning the API surface may change. But the direction is clear: MCP is becoming a bidirectional messaging layer, not just a tool-calling protocol.

Skills learn to set their own pace

Section titled “Skills learn to set their own pace”

effort frontmatter in skills and slash commands lets the skill author override the model’s effort level when the skill is invoked.

Before this, effort was a global setting. You’d set it high for complex work, low for quick tasks, and toggle back and forth. Now the skill decides. A code formatting command runs at minimal effort because it doesn’t need deep reasoning. An architecture review skill demands maximum effort because shortcuts produce bad analysis.

This is a small YAML field with outsized impact. Skill authors can now design for the right level of reasoning rather than hoping the user has their effort setting dialed correctly.

Rate limits, visible

Section titled “Rate limits, visible”

rate_limits is a new field available to statusline scripts. It exposes Claude.ai’s 5-hour and 7-day usage windows with used_percentage and resets_at.

If you’ve ever been surprised by hitting a rate limit mid-task, this is the fix. Your statusline can now show something like “73% of 5h limit used, resets in 2h”. No more guessing.

This only applies to Claude.ai billing. API users with their own keys have different limits.

MCP elicitation

Section titled “MCP elicitation”

This is the headline. Until now, MCP tool calls were strictly request-response: Claude Code sends a request, the server sends back data. If the server needed additional information from you — credentials, a configuration choice, a confirmation — it had no way to ask.

MCP elicitation changes that. An MCP server can now send an elicitation request during a tool call. Claude Code renders it as an interactive dialog: form fields for structured input, or a browser URL for OAuth-style flows. You respond, and the server continues with your answer.

Two new hooks accompany this:

  • Elicitation fires when an MCP server requests input, before the dialog is shown. You can inspect, modify, or auto-respond.
  • ElicitationResult fires after you respond, before the result is sent back to the server. You can override or log what’s being returned.

This matters because it turns MCP tools from passive data sources into interactive collaborators. A database tool can ask which schema to use. A deployment tool can request confirmation before applying changes. An auth tool can redirect you to a login page and wait for the token.

Section titled “Deferred tools: schema loss after compaction”

What is BMAD + Quick Dev Flow + YOLO Mode?

Section titled “What is BMAD + Quick Dev Flow + YOLO Mode?”

Three concepts combine to make this workflow possible.

BMAD stands for Business-Module-Architecture-Development. It is a structured development methodology that moves through four phases: define business requirements, design the module boundary, make architecture decisions, then execute development. The key value is that it produces a compact, machine-readable spec that an AI agent can consume without ambiguity.

Quick Dev Flow (/bmad-bmm-quick-dev) is the fast lane within BMAD. It reads the spec, analyzes the existing codebase for patterns and conventions, implements the feature, runs the tests, and fixes failures. One command kicks off the entire pipeline.

YOLO mode tells Claude Code to operate autonomously. No confirmation dialogs. No “should I proceed?” interruptions. It reads, writes, runs commands, and iterates until done.

The combination works because BMAD provides the guardrails — conventions, patterns, architecture constraints — while YOLO removes friction. The agent knows what to build (from the spec) and how to build it (from analyzing your codebase). You just let it run.

Section titled “Key Takeaways”

1. YOLO mode works best with strong conventions. The Rails backend was nearly perfect on the first pass. Why? Because the codebase had consistent, discoverable patterns. 2. Frontend frameworks carry more implicit knowledge. Four of five issues were Angular-side. UI component libraries have undocumented prop names. Routing has implicit conventions about path prefixes. 5. Test-first validates backend. User-first validates frontend. RSpec caught backend issues before they reached a browser. But frontend issues only surfaced when a human looked at the rendered page. This asymmetry is structural: backend behavior is fully testable through integration specs; frontend behavior depends on visual correctness, component library quirks, and interaction flows that automated tests do not cover well without dedicated E2E suites.

Claude Code 2.1.69: Twenty Small Cuts That Sharpen the Platform

Mar 5, 2026
Vibe Sparking

Claude Code 2.1.69: Twenty Small Cuts That Sharpen the Platform

Section titled “Claude Code 2.1.69: Twenty Small Cuts That Sharpen the Platform”

Twenty features. None of them headline-worthy on its own. That’s exactly why this release matters.

Between February 5 and February 28, Claude Code shipped a multi-agent platform — Opus 4.6, agent teams, worktree isolation, remote control, persistent memory, HTTP hooks. Eight releases in fifteen days. Impressive, and rough around the edges.

2.1.69 (March 4) does the harder work: it makes that platform comfortable. Skills know where they live. Hooks know which agent triggered them. Your terminal shows what effort level is active. Plugins reload without restarting. These are ergonomics — and ergonomics decide whether powerful tools get used or shelved.

Skills Ecosystem

Section titled “Skills Ecosystem”

Two additions that change how skills work in practice.

/claude-api skill — A built-in skill for building applications with the Claude API and Anthropic SDK. Instead of remembering SDK patterns or searching docs, you get guided assistance for API integration directly inside Claude Code.

${CLAUDE_SKILL_DIR} variable — Skills can now reference their own directory in SKILL.md content. Before this, a skill that needed to load a template or data file from its own directory had to use absolute paths or fragile relative references. Now:

This matters for portable, shareable skills. A skill published as a plugin works the same regardless of where it’s installed.

Plugin Infrastructure

Section titled “Plugin Infrastructure”

Four changes that make the plugin ecosystem more enterprise-ready.

/reload-plugins — Activate pending plugin changes without restarting Claude Code. During plugin development, this cuts the feedback loop from “restart session, lose context” to “reload, keep working.”

pluginTrustMessage — Managed settings can now append organization-specific context to the plugin trust warning shown before installation. An enterprise admin can add “Only install plugins from our internal marketplace at plugins.corp.internal” directly into the trust dialog.

pathPattern in strictKnownMarketplaces — Regex matching for file and directory marketplace sources, alongside existing hostPattern restrictions. More granular control over where plugins come from.

git-subdir plugin source — Point to a subdirectory within a git repo. A monorepo with five plugins no longer needs five separate repos.

Hooks Evolution

Section titled “Hooks Evolution”

Three features that give hooks better awareness of the platform’s internal state.

InstructionsLoaded hook event — Fires when CLAUDE.md or .claude/rules/*.md files are loaded into context. An enterprise security team can audit which instruction files are active. A development workflow can trigger actions when project rules change.

agent_id and agent_type in hook events — Every hook event now carries the identity of the agent that triggered it. agent_id for subagents, agent_type for both subagents and --agent sessions. A PreToolUse hook can now apply different policies to different agents — let the code-writer use Bash freely, restrict the code-reviewer to Read-only.

worktree field in status line hook commands — When running in a --worktree session, hooks receive name, path, branch, and original repo directory. A CI integration can track which worktree is running what.

UX Polish

Section titled “UX Polish”

Small changes to the daily interaction surface.

Ctrl+U on empty bash prompt exits bash mode — Matches the existing Escape and Backspace behavior. One more muscle memory path that works as expected.

Numeric keypad support — Interview questions (those numbered option lists Claude presents) now accept input from the numeric keypad, not just the number row above QWERTY. If you’ve been jabbing the numpad and wondering why nothing happened, that’s fixed.

Effort level in spinner — The logo and spinner now display the active effort setting (e.g., “with low effort”). Before, you had to check /config to remember what effort level was active. Now it’s visible whenever Claude is thinking.

Agent name in terminal title — When using claude --agent, the terminal title shows the agent name. With multiple terminal tabs running different agents, you can tell them apart at a glance.

Claude Code Desktop prompt — A one-time startup suggestion for Claude Code Desktop on macOS and Windows. Shown up to 3 times, then dismissed permanently. Low friction, easy to ignore.

Configuration

Section titled “Configuration”

Two settings for specific environments.

sandbox.enableWeakerNetworkIsolation (macOS only) — Allows Go programs like gh, gcloud, and terraform to verify TLS certificates when using a custom MITM proxy with httpProxyPort. Corporate networks with TLS inspection proxies need this.

includeGitInstructions — Removes built-in commit and PR workflow instructions from Claude’s system prompt. Also available as CLAUDE_CODE_DISABLE_GIT_INSTRUCTIONS env var. Useful if you have custom commit workflows in your CLAUDE.md and don’t want Claude’s defaults conflicting.

Remote Control Enhancement

Section titled “Remote Control Enhancement”

Optional name argument — /remote-control My Project or --name "My Project" sets a custom session title visible in claude.ai/code. When you’re monitoring multiple remote sessions from your phone, names beat auto-generated IDs.
