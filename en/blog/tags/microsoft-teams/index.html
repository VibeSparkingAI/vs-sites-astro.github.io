Section titled “1. Gateway/OpenAI compatibility”

Change: Added /v1/models, /v1/embeddings endpoints, and forward explicit model parameters through /v1/chat/completions and /v1/responses.

Background: OpenClaw’s Gateway exposes an OpenAI-compatible HTTP API, allowing third-party clients (like Cursor, Continue, LibreChat, Dify) to use OpenClaw as an OpenAI proxy. Previously missing /v1/models (for client model enumeration) and /v1/embeddings (essential for RAG pipelines) caused many client integrations to fail or have incomplete functionality.

Usage Examples:

  • You configure a custom OpenAI endpoint in Dify pointing to http://localhost:3000/v1 - previously Dify calling /v1/models would 404, now it can fetch the model list normally
  • LangChain’s OpenAIEmbeddings class sending requests to /v1/embeddings - previously would fail, now OpenClaw can proxy to backend embedding models
  • Specifying "model": "claude-opus-4-6" in /v1/chat/completions request body - previously might be ignored using default model, now correctly forwarded

Notes:

  • /v1/models returns a list based on Gateway-configured providers/models, not OpenAI’s full model catalog
  • /v1/embeddings requires a configured backend embedding model (like text-embedding-3-small), otherwise returns error
  • Model override forwarding means clients can override agent default models - be aware if you have permission controls

Section titled “Beta to Stable: A 3-Day Convergence”

Security Fix: Media Path Alias Sandbox Bypass

Section titled “Security Fix: Media Path Alias Sandbox Bypass”

This is the most important fix in this release.

Problem: Outbound tools and message actions could bypass media-root restrictions through mediaUrl or fileUrl alias fields, accessing files outside the sandbox. A malicious prompt injection could trick an agent into reading /etc/passwd via fileUrl and sending it externally.

Root cause: Security boundary checks only covered primary path fields. Alias fields were unchecked.

Impact: Multi-tenant OpenClaw deployments are at highest risk. Single-user setups are less exposed but should still upgrade.

Path traversal via alias fields is a classic web security issue. Jupyter Notebook and Code Server have both had similar vulnerabilities. This fix unifies all path fields under the same security check.

Bug Fixes: 16 Items in Stable Changelog

Section titled “Bug Fixes: 16 Items in Stable Changelog”

Outbound Media/Local Files: Policy Alignment

Section titled “Outbound Media/Local Files: Policy Alignment”

Sending host-machine local files failed when workspaceOnly was off. File sending used different permission logic than file reading. If you worked around this by copying files into the workspace, you can remove that workaround.

Gateway Restart Session Recovery

Section titled “Gateway Restart Session Recovery”

After a gateway restart, interrupted sessions got a best-effort restart notification but thread/topic routing information could be lost. Now uses heartbeat-based wakeup, preserves routing info, and retries failed outbound delivery once.

Docker First-Install Boot Loop

Section titled “Docker First-Install Boot Loop”

Fresh Docker installs got stuck in a loop: the CLI tried to connect to the gateway before it started, but the gateway needed config that the CLI was supposed to write. Classic chicken-and-egg. Fixed by writing config through the gateway process directly, bypassing network dependency.

Channel Startup Fault Isolation

Section titled “Channel Startup Fault Isolation”

An expired Telegram bot token would take down not just Telegram but Discord and WhatsApp too. Channels started serially with no try-catch isolation. Now each channel fails independently. This is the bulkhead pattern applied to channel startup.

WhatsApp Echo Suppression

Section titled “WhatsApp Echo Suppression”

In groups, gateway-sent messages were processed as new inbound messages, creating reply loops. The fix also stopped suppressing owner commands sent from linked accounts. Now tracks recently sent message IDs and only suppresses matching echoes.

WhatsApp Reply-to-Bot Detection

Section titled “WhatsApp Reply-to-Bot Detection”

Replying to a bot message in a group to trigger the bot stopped working. The bot’s selfLid was being read differently. WhatsApp’s linked account mode, where bot and owner share one number, is the root complexity here.

Telegram Forum #General Topic Routing

Section titled “Telegram Forum #General Topic Routing”

The #General topic (topic ID = 1) in Telegram forum mode failed to route when Telegram omitted forum metadata. If you use OpenClaw in Telegram forum groups, upgrade for this fix.

Discord Gateway Crash Elimination

Section titled “Discord Gateway Crash Elimination”

Discord server disconnects caused full process crashes instead of graceful reconnection. Lifecycle errors during startup, runtime, and teardown phases are now properly classified and handled.

Discord Timeout Visible Replies

Section titled “Discord Timeout Visible Replies”

When a Discord worker timed out (agent thinking too long), users saw nothing. Now sends a visible timeout message.

ACP Direct Chats TTS Empty Audio

Section titled “ACP Direct Chats TTS Empty Audio”

In voice conversation mode, if TTS synthesis failed, neither audio nor text was delivered. Now falls back to text delivery when TTS returns empty audio.

Telegram 403 Error Handling

Section titled “Telegram 403 Error Handling”

After a bot was kicked from a group, queued messages kept retrying forever. Now preserves specific 403 reasons (blocked/kicked/not a member) and marks “bot not a member” as permanent failure to stop retries.

Telegram Photo Size Preflight

Section titled “Telegram Photo Size Preflight”

Uploading photos that didn’t meet Telegram’s dimension requirements failed with PHOTO_INVALID_DIMENSIONS. Now checks dimensions before sending and falls back to document upload. Telegram rules: longest side under 1280px, aspect ratio under 20:1.

Slack DM Reply Optimization

DM replies had unnecessary overhead, and web-search was triggered automatically when it shouldn’t have been. Streamlined reply logic, web-search changed to explicit opt-in.
