Claude Code 2.1.85 Deep Dive: Feature-by-Feature Analysis, Cross-Product Comparison & Evolution Trends

Mar 27, 2026
Vibe Sparking

Release Overview

Section titled “Release Overview”

2.1.85 is a “platform maturity” release — 9 new features + 17 bug fixes + 4 performance optimizations — centered on four themes: MCP ecosystem standardization, enterprise-grade hooks, terminal experience polish, and large-session stability.

New Features: Feature-by-Feature Analysis

Section titled “New Features: Feature-by-Feature Analysis”

1. MCP Multi-Server Environment Variables (CLAUDE_CODE_MCP_SERVER_NAME / CLAUDE_CODE_MCP_SERVER_URL)

Section titled “1. MCP Multi-Server Environment Variables (CLAUDE_CODE_MCP_SERVER_NAME / CLAUDE_CODE_MCP_SERVER_URL)”

Background: Previously, an MCP header helper script could only be hard-coded to serve one specific MCP server. If you had five MCP servers, you needed five nearly identical helper scripts.

Use cases:

  • An enterprise runs jira-mcp, confluence-mcp, and sentry-mcp — all of which need an OAuth Bearer token header injected in the same format
  • You can now write a single generic helper: #!/bin/bash echo "Authorization: Bearer $(get_token $CLAUDE_CODE_MCP_SERVER_NAME)"
  • At runtime, Claude Code automatically injects the current server’s name and URL

Notes: The helper script must be able to return different tokens dynamically based on server name/URL. Do not use a globally fixed value.

Cross-product comparison:

ProductMCP Header Customization
Claude CodeEnvironment variable injection — one helper serves multiple servers
Codex CLINo MCP support (OpenAI uses its own plugin system)
Gemini CLISupports MCP, but header customization is less granular than Claude Code

Trend: MCP header customization exists to accommodate enterprise authentication gateways and zero-trust network architectures. This may eventually evolve into declarative auth config (similar to Kubernetes ServiceAccount token auto-mounting).

2. Conditional Hook Execution (if Field with Permission-Rule Syntax)

Section titled “2. Conditional Hook Execution (if Field with Permission-Rule Syntax)”

Background: The previous hook system fired on everything — every PreToolUse event would fork a process to run the hook script, even if that hook only cared about git commands. Frequent process forking means added latency and wasted CPU.

Use case:

This triggers only when a git-related Bash command is executed; all other Bash calls (npm, python, etc.) are skipped outright.

Notes:

  • The if syntax reuses the permission-rule pattern-matching format (Bash(git *) means: the Bash tool, with arguments matching git *)
  • Non-matching hooks spawn no processes at all — it’s a pure string-match skip
  • Be careful with wildcard scope: Bash(rm *) will match rm -rf /

Cross-product comparison:

ProductHook Conditional Filtering
Claude Codeif condition using permission-rule syntax
Codex CLIHas a hook system but no conditional filtering; uses layered sandbox policies instead
Gemini CLINo hook system; uses coarse-grained tool policies

Trend: The hook system is evolving toward a “lightweight policy engine.” The progression goes: conditional matching → condition chains → a full declarative policy engine akin to OPA/Rego.

3. Scheduled Task Timestamp Markers (/loop and CronCreate transcript labels)

Section titled “3. Scheduled Task Timestamp Markers (/loop and CronCreate transcript labels)”

Background: When running tasks via /loop or cron, the transcript contained no record of when each execution was triggered. After the fact, there was no way to distinguish manual from automated triggers or reconstruct the timeline.

Use case:

  • You configure /loop to check CI status every 10 minutes
  • The transcript now shows entries like [2026-03-27 14:30:00 UTC — /loop triggered]
  • When reviewing a session, it’s immediately clear which actions were automated

Notes: Timestamps are in UTC. You’ll need to convert to local time manually.

Cross-product comparison:

ProductScheduled Task Auditability
Claude CodeInline timestamps embedded in the transcript
Codex CLINo built-in loop/cron mechanism
Gemini CLITask tracker was just integrated into the system prompt; no time markers yet

Trend: Auditability for AI agents is a hard requirement in enterprise procurement. This will likely evolve into OpenTelemetry span-level tracing.

4. Trailing Space After Pasted Image Placeholders ([Image #N] followed by a space)

Section titled “4. Trailing Space After Pasted Image Placeholders ([Image #N] followed by a space)”

Background: After pasting an image, the [Image #1] placeholder was immediately followed by user-typed text, causing the tokenizer to potentially merge the placeholder and the text.

Use case: After pasting a screenshot and typing “fix this CSS,” the result used to be [Image #1]fix this CSS. It now correctly produces [Image #1] fix this CSS.

Notes: A minor change, but important for the robustness of multimodal interactions.

Cross-product comparison: All three products support image pasting in similar ways. This is a polish-level detail that does not represent a competitive differentiator.

5. Deep Link Length Extended to 5,000 Characters

Section titled “5. Deep Link Length Extended to 5,000 Characters”

Background: The claude-cli://open?q=... deep link had a short character limit that prevented passing complex pre-filled prompts. CI/CD tools and IDE plugins wanting to open Claude Code with full context would have their payloads truncated.

Use cases:

  • A CI pipeline failure automatically generates a deep link: claude-cli://open?q=This%20build%20failed%20with%20error... (with the full error log attached)
  • Internal team wikis embed one-click debug links
  • Prompts that exceed a readable length display a “scroll to review” warning to prevent blind execution

Notes: The 5,000-character limit applies to the URL-encoded string; the actual content is shorter. Browsers also impose their own limits on total URL length.

Cross-product comparison:

ProductDeep Link / URL Scheme
Claude Codeclaude-cli://open?q=..., up to 5,000 characters
Codex CLINo standard deep link scheme
Gemini CLINo standard deep link scheme

Trend: Deep links are the bridge for IDE-to-CLI integration. A standardized coding agent URL scheme protocol is a likely future development.

6. MCP OAuth RFC 9728 Compliance

Section titled “6. MCP OAuth RFC 9728 Compliance”

Background: MCP OAuth previously used a custom discovery mechanism to locate the authorization server. RFC 9728 (Protected Resource Metadata), which became a standard in late 2024, defines how a resource server can advertise its associated authorization server for automatic discovery.

Use case:

  • The MCP server returns WWW-Authenticate: Bearer plus a resource_metadata URL
  • Claude Code automatically fetches that URL to retrieve authorization_server information
  • Users no longer need to manually configure the OAuth issuer, token endpoint, or other parameters

Notes:

  • The MCP server must also implement the RFC 9728 metadata endpoint
  • There may be transitional compatibility issues with the older discovery mechanism

Cross-product comparison:

ProductOAuth Standards Compliance
Claude CodeRFC 9728 discovery
Codex CLIN/A (does not use MCP OAuth)
Gemini CLIMCP support in progress; OAuth implementation details not yet public

Trend: MCP ecosystem authentication is converging from “every vendor rolling their own” toward RFC-standard flows. This is critical for enterprise SSO integration.

7. Organization Policy Blocks Plugin Installation (managed-settings.json)

Section titled “7. Organization Policy Blocks Plugin Installation (managed-settings.json)”

Background: Enterprise IT teams need control over which plugins can be installed. Previously, managed-settings.json could flag blocked plugins, but those plugins remained visible in the marketplace — users could see them but not install them, creating a confusing experience.

Use case: A company’s security policy prohibits all third-party shell-execution plugins. Those plugins now disappear entirely from the marketplace, so employees never encounter the confusing “why can’t I install this?” situation.

Notes: This is an organization-level setting and does not affect individual users. IT admins must maintain managed-settings.json.

Cross-product comparison:

ProductEnterprise Plugin Management
Claude Codemanaged-settings.json + marketplace hiding
Codex CLIProduct-scoped plugin sync just landed in v0.117
Gemini CLIHas a settings.json policy but no marketplace integration

Trend: All three vendors are accelerating enterprise control capabilities. The end state will likely align with MDM (Mobile Device Management)-level policy distribution.

8. PreToolUse Hook Satisfying AskUserQuestion (Headless Integration)

Section titled “8. PreToolUse Hook Satisfying AskUserQuestion (Headless Integration)”

Background: When Claude Code needs to ask the user a question (AskUserQuestion) in a headless or CI environment, there is no human available to respond. Previously, execution would simply time out and fail.

Use case:

The hook script returns {"permissionDecision": "allow", "updatedInput": "Yes, proceed with the refactor"}, automatically answering on behalf of the user.

This enables Claude Code to run fully unattended:

  • Automatically fixing lint issues in CI/CD
  • Batch refactoring tasks
  • Bridging user Q&A through a Slack bot

Notes:

  • Design the auto-answer logic carefully to avoid automatically saying “yes” when the agent is about to perform a dangerous operation
  • Pairing this with if conditional filtering is recommended so that only specific question types are auto-answered

Cross-product comparison:

ProductHeadless Auto-Response
Claude CodeHook returns updatedInput
Codex CLISupports --yes for global auto-approval, but without fine-grained control
Gemini CLINo comparable mechanism

Trend: This is a key piece of the “Agent-as-a-Service” puzzle. A complete Human-in-the-Loop API with routing to Slack/Teams/webhooks is a likely future development.

9. OTEL tool_parameters Gating (OTEL_LOG_TOOL_DETAILS=1)

Section titled “9. OTEL tool_parameters Gating (OTEL_LOG_TOOL_DETAILS=1)”

Background: tool_result events in OpenTelemetry traces include tool parameters by default, which can expose sensitive information — API keys, file contents, and so on — to monitoring systems.

Use case:

  • Production environments default to off: tool parameters are not recorded in OTEL logs
  • When debugging, set OTEL_LOG_TOOL_DETAILS=1 to enable full parameter logging

Notes: The default behavior has changed. Previously, parameters were always logged. Now they are not logged by default. If your monitoring pipeline depends on this data, you must opt in explicitly.

Cross-product comparison:

ProductOTEL Privacy Control
Claude CodeEnvironment variable gating
Codex CLISupports OTEL but no fine-grained gating
Gemini CLINo OTEL integration yet

Trend: Observability and privacy compliance are two sides of the same coin. Field-level redaction standards for OTEL are a likely future development.

Bug Fixes: Fix-by-Fix Analysis

Section titled “Bug Fixes: Fix-by-Fix Analysis”

Fix 1: /compact Fails on Oversized Conversations (“context exceeded”)

Section titled “Fix 1: /compact Fails on Oversized Conversations (“context exceeded”)”

Background: The /compact command works by sending the conversation to the LLM for summarization. When the conversation has grown so large that even the compact request itself exceeds the context window, execution enters a deadlock — it’s too large and needs compacting, but the compact operation itself is also too large to run.

Resolution: Likely implemented as a segmented compression approach or a truncate-then-compact strategy.

Cross-product comparison: Codex’s compaction now runs in the background to reduce UI blocking (see performance comparison below). Gemini CLI has no equivalent feature.

Fixes 2–3: Plugin Enable/Disable Path Mismatch & Worktree Error in Non-Git Repositories

Section titled “Fixes 2–3: Plugin Enable/Disable Path Mismatch & Worktree Error in Non-Git Repositories”

Background:

  • When the declared plugin location (in settings) and the actual installation location differ, enable/disable operations cannot find the file
  • Using --worktree in a non-git directory caused an immediate crash before the WorktreeCreate hook could even run

Cross-product note: Codex v0.117 also recently fixed a plugin gating-related bug.

Fix 4: deniedMcpServers Not Blocking claude.ai MCP Servers

Section titled “Fix 4: deniedMcpServers Not Blocking claude.ai MCP Servers”

Background: The deniedMcpServers security setting only blocked MCP servers configured through the CLI, not those passed through from the claude.ai web interface. This was a security vulnerability — the enterprise-configured blocklist could be bypassed.

Cross-product note: This is a Claude Code-specific issue, as it is the only product that connects to both CLI and web MCP sources simultaneously.

Fix 5: switch_display Not Working in Multi-Monitor Setups

Section titled “Fix 5: switch_display Not Working in Multi-Monitor Setups”

Background: The Computer Use tool’s switch_display action was returning “not available” in multi-monitor environments. Multi-monitor configurations are common in enterprise settings where computer use automation is relevant.

Cross-product note: Codex and Gemini CLI do not have built-in computer use capabilities.

Fix 6: Crash When OTEL Exporter Is Set to none

Section titled “Fix 6: Crash When OTEL Exporter Is Set to none”

Background: Setting OTEL_LOGS_EXPORTER=none to disable log export caused the program to crash. This was a straightforward null-value handling bug.

Fix 7: Diff Syntax Highlighting Broken in Non-Native Builds

Section titled “Fix 7: Diff Syntax Highlighting Broken in Non-Native Builds”

Background: Non-native builds packaged via pkg/bun were missing the tree-sitter WASM bindings.

Fix 8: MCP Step-Up Authorization Failure (When a Refresh Token Is Present)

Section titled “Fix 8: MCP Step-Up Authorization Failure (When a Refresh Token Is Present)”

Background: OAuth includes a “step-up auth” scenario where the user is already logged in but the server requires elevated permissions (for example, accessing sensitive data requires MFA). The server returns 403 insufficient_scope. When a refresh token is already present locally, the code incorrectly attempted to refresh rather than re-authenticate.

Example: An MCP server requires scope: admin:write, but the local token only has scope: read. The server returns 403. Claude Code should prompt for re-authorization rather than looping with the old refresh token.

Trend: As MCP servers integrate with enterprise IAM systems, step-up auth scenarios will become increasingly common.

Fixes 9–10: Remote Session Memory Leak & Persistent ECONNRESET Errors

Section titled “Fixes 9–10: Remote Session Memory Leak & Persistent ECONNRESET Errors”

Background:

  • In remote sessions, when a streaming response was interrupted, the response buffer was not released, causing memory to grow indefinitely
  • The edge connection layer was repeatedly retrying the same broken TCP connection on instability; this has been changed so each retry uses a fresh TCP connection

Cross-product note: Codex v0.117 also fixed similar stability issues in remote multi-agent sessions.

What Actually Killed It

My first assumption was SSH — maybe the Tokyo server has an aggressive ClientAliveInterval, or the connection timed out overnight. I started there.

The real culprit showed up when I tried to reattach:

Not “session not found.” Not “connection lost.” The entire tmux server was gone. That’s a different failure mode.

Why tmux Doesn’t Survive on macOS

Section titled “Why tmux Doesn’t Survive on macOS”

tmux is a user-space process. When macOS sleeps — or you close the lid, or the machine restarts — the OS tears down user processes that aren’t managed by launchd. There’s no graceful shutdown, no state preservation. The tmux server just vanishes.

This is by design. macOS doesn’t treat tmux as a service. It doesn’t know that tmux was babysitting an SSH tunnel that something else depends on. From the OS’s perspective, it’s just another process attached to your terminal session.

On Linux with systemd you’d write a unit file and call it a day. On macOS, the equivalent is launchd — and most people never use it for personal tooling because it feels like overkill. It isn’t.

The Fix: launchd + autossh

Section titled “The Fix: launchd + autossh”

autossh wraps an SSH connection and restarts it when it drops. Combined with launchd, you get a tunnel that:

  • Starts automatically on login
  • Restarts if the SSH connection dies
  • Survives sleep and wake cycles
  • Doesn’t need a terminal window open to stay alive

Section titled “Setting Up the plist”

Create the launchd agent file at ~/Library/LaunchAgents/com.openclaw.tunnel-s8.plist. Name it whatever makes sense for your setup — the reverse-DNS prefix is convention, not requirement.

A few things worth explaining in the autossh flags:

  • -M 0 disables autossh’s own monitoring port. We’re relying on SSH’s built-in keepalives instead, which is cleaner.
  • ServerAliveInterval=30 and ServerAliveCountMax=3 mean SSH will detect a dead connection within 90 seconds and exit, letting autossh restart it.
  • ExitOnForwardFailure=yes tells SSH to bail if the port forward can’t be established — rather than connecting successfully but silently failing to set up the tunnel.
  • -N means no remote command; we just want the tunnel.

The constraints you designed around might disappear mid-project. You’re building on ground that’s rising underneath you.

This isn’t a metaphor. If you built a six-month roadmap this year, by month three a new model drops and the technical assumptions from months one and two may already be outdated.

Roles Are Blending

Section titled “Roles Are Blending”

What does Anthropic’s Claude Code team look like now? Designers ship code directly. Engineers make product decisions. PMs build prototypes and write evals.

Sounds like organizational chaos. It’s the opposite. This works because the team has very clear strategic direction and goals, so everyone can prioritize independently.

The PM’s core job becomes three things:

Create clarity in ambiguity. Models improve fast, possibilities explode, and it’s easy to get lost between “we can do this” and “we should do this.” The PM cuts through that fog.

Push the team to think bigger. Many people, PMs included, underestimate what new models can do. Cat Wu’s advice: use your own product every day and deliberately ask it to do things you think are too hard. Sometimes it works — and that’s a signal the product needs to catch up.

Remove obstacles. Fewer meetings, less process, so engineers and designers can ship faster.

Four Battle-Tested Shifts

Section titled “Four Battle-Tested Shifts”

1. Drop the Long Roadmap, Run Short Sprints

Section titled “1. Drop the Long Roadmap, Run Short Sprints”

Cat Wu uses a term: side quest.

Encourage everyone on the team — engineers, PMs, designers — to spend half a day trying their own idea. Not on the official roadmap. No approval needed. Just see if it works.

Several of Claude Code’s most popular features came from side quests: Claude Code on Desktop, AskUserQuestion, todo lists. None were formally planned.

For PMs, this means your roadmap is no longer the sole source of product direction. You need mechanisms for good side-quest experiments to surface, get validated, and merge into the main line.

2. Prototypes Over Documentation

Section titled “2. Prototypes Over Documentation”

Cat Wu describes a key transition:

Replaced documentation-first thinking with prototype-first thinking.

After writing a spec, don’t schedule a review meeting. Throw it at Claude Code and see if it can produce a working prototype. One afternoon is enough to validate whether an idea is worth pursuing.

Wrong bets are cheap. Spending half a day to discover a dead end beats spending two weeks on detailed designs before reaching the same conclusion.

For more abstract products like agent teams, they use hand-crafted evals to measure outcomes. Not documents saying “we believe this is good” — actual test runs with real data.

3. Every New Model Is a Reason to Revisit

Section titled “3. Every New Model Is a Reason to Revisit”

This one’s easy to miss.

A new model release isn’t just “faster.” It may mean all the workarounds you added for model limitations can be deleted. Cat Wu gave an example: the todo list feature originally required system prompts reminding the agent to update its status every few messages. The next model did this natively. The reminders were removed. Opus 4.6 trimmed 20% of their system prompts.

She also shared a detection method: watch what users are manually stitching together. User-built workarounds are features you should be building. Chrome integration came from observing users constantly pasting web content into conversations.

4. Do the Simple Thing

Section titled “4. Do the Simple Thing”

This sounds like generic advice, but Cat Wu gave a specific reason:

If your product cleverly works around a model limitation, that workaround becomes unnecessary complexity when the next model drops.

Your clever solution for today’s model limitation becomes dead weight tomorrow. Simpler code means easier capability swaps.

On cost, she made a particularly useful point:

Always optimize for capability first. Use more tokens than you think you need. It’s a common mistake to cut token costs too early.

Figure out whether the feature is even possible first. Don’t cut tokens at the start. Too many teams prematurely optimize costs and ship a crippled product. Costs come down later as cheaper models catch up. But first you need to know where the ceiling is.

The New PM Mindset

Section titled “The New PM Mindset”

Cat Wu compared this state to surfing:

It feels like surfing a wave where the most important thing is to stay on it.

Not controlling the wave. Just staying on it.

For many PMs, this shift is hard to accept. We’re used to tight control over the product experience, every detail flowing through us. But AI pushes you to let go.

Her advice: identify the handful of true non-negotiables and release everything else. “Human on the loop, not in the loop” — supervising, not blocking every decision.

Track two things simultaneously:

  • How AI is changing the way you work
  • How AI is changing what’s possible in your product

When a PM can go from idea to working prototype in an afternoon, the gap between “what if we tried…” and “here, try this” nearly disappears.

Be the One Who Sees It Coming

Section titled “Be the One Who Sees It Coming”

Honestly, the biggest feeling after reading this article wasn’t anxiety. It was urgency.

These changes aren’t future tense. Anthropic is already working this way, and it’s working well. Claude Code’s growth in the AI coding tool space speaks for itself.

The only difference is whether you’re the one who sees the change coming, or the last one to be surprised.

If you’re a PM, start small. Tomorrow, take half a day with an idea you’ve been assuming is “too complex to build.” Try prototyping it with an AI tool. Maybe it really can’t be done. Maybe it can — and then you’ll rethink a few things.

Either way, you’ll know where you stand better than you do today.

What It Is

Section titled “What It Is”

macos-use is an MCP server written in Swift. It lets Claude — or any MCP-compatible model — control desktop applications through macOS Accessibility APIs.

Not screenshots. The accessibility tree.

Every UI element in every macOS app — buttons, text fields, menus, lists — is exposed through Accessibility APIs as structured, hierarchical data. VoiceOver has relied on this for decades. Automated testing tools use it. macos-use connects this tree directly to Claude via MCP.

Instead of analyzing a 1200×800 image and guessing coordinates, the AI reads: AXButton, label="Send", enabled=true. Unambiguous. Resolution-independent. No vision model required.

Why Not Screenshots

Section titled “Why Not Screenshots”

The screenshot approach has three hard problems.

Token cost. A 1080p screenshot dropped into context is expensive. macos-use returns compact JSON file paths — UI trees are saved to /tmp/macos-use/, not dumped into the model’s context window.

Unreliability. Pixel-based recognition depends on display resolution, scaling, dark mode, font rendering. Change monitors or toggle Dark Mode and coordinates shift. The accessibility tree is structural data — none of that matters.

No semantics. In a screenshot, the AI guesses whether something is a button and what it does. The accessibility tree says: AXButton, label="Send", enabled=true. No inference required.

Caveats

Section titled “Caveats”

Coordinates are window-relative. click_and_traverse x/y coordinates are relative to the target app’s window, not the screen. If the window moves, stored coordinates need to be recalculated.

Unstable during animations. The accessibility tree is a snapshot. If an app is mid-transition, refresh_traversal may need to wait for the animation to finish before the state is accurate.

macOS only. No Windows, no Linux. Swift + macOS Accessibility APIs are platform-bound.
