OpenClaw 2026.4.7 Bug Fixes Deep Analysis

Apr 8, 2026
Vibe Sparking

This document provides a deep analysis of all 71 bug fixes in the OpenClaw 2026.4.7 release.

1. CLI/infer: Align Inference Behavior with Actual Runtime Execution

Section titled “1. CLI/infer: Align Inference Behavior with Actual Runtime Execution”

Fix Summary

Section titled “Fix Summary”

Fixed multiple inconsistencies between openclaw infer CLI command and the actual runtime, including TTS overrides, profile-aware gateway TTS preferences, transcription prompt/language overrides, image output MIME/extension mismatch, web-search fallback, and agent vs CLI web-search behavior drift.

Background

Section titled “Background”

openclaw infer as a standalone CLI inference command should produce results identical to the agent runtime. However, as features evolved, the two paths diverged: TTS configuration didn’t read profile-level preferences, transcription ignored user-specified prompt and language parameters, image generation MIME types didn’t match file extensions (e.g., returning PNG data but labeling as .jpg), and web-search had fallback logic in the agent but not in CLI. The root cause was insufficient code sharing between infer and agent paths.

Impact

Section titled “Impact”
  • Voice generated via openclaw infer --tts differed from agent conversations
  • Image file extensions didn’t match actual content, causing viewer failures
  • Web-search results differed between CLI and agent, breaking automation scripts

2. Plugins/media: Merge Capability Plugin IDs into Allowlist

Section titled “2. Plugins/media: Merge Capability Plugin IDs into Allowlist”

Fix Summary

Section titled “Fix Summary”

When plugins.allow is set, the capability fallback logic now merges built-in capability plugin IDs into the allow list, so OpenAI-compatible STT and other media providers load without explicitly declaring openai in plugins.allow. (#62205)

Background

Section titled “Background”

OpenClaw’s plugin security model lets users restrict loadable plugins via plugins.allow. But built-in “capability plugins” (like STT providers) are core platform features, not third-party plugins. The previous implementation only merged IDs from plugins.entries, missing built-in capability plugin IDs.
